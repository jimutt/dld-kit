id: DL-001
title: Validate all user-supplied input before processing
status: proposed
tags: [validation, security]

## Context

The `process_data` function in `src/processor.py` currently accepts raw dictionaries from external callers without checking whether required fields are present or whether values are the expected type. In production, malformed inputs have caused cryptic `KeyError` and `TypeError` exceptions deep inside the processing logic, making debugging difficult and occasionally corrupting the output record.

## Decision

Introduce a dedicated `validate_input(data)` function that checks all user-supplied input before any processing occurs. The function must raise a `ValueError` with a descriptive message if validation fails. `process_data` must call `validate_input` as its first step, before any transformation logic executes.

## Rationale

Catching bad input at the boundary — before it enters the processing pipeline — produces clear, actionable error messages and prevents partial writes. It also satisfies the single-responsibility constraint in DL-000: `validate_input` owns input checking; `process_data` owns transformation.

## Consequences

All callers that pass incomplete or wrongly-typed data will now receive explicit `ValueError` exceptions instead of cryptic internal errors. The validation logic lives in one place and must be updated whenever new required fields are added to the schema.
