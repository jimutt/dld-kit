## Context

The application calls several downstream APIs repeatedly with the same parameters. Response latency was causing poor user experience and unnecessary load on upstream services.

## Decision

Implement an in-memory LRU (Least Recently Used) cache for API responses with a configurable TTL. The cache will be keyed by the request URL and query parameters.

## Rationale

An in-memory LRU cache is simple to implement, has zero infrastructure dependencies, and delivers low latency hits. For our current scale, this is sufficient. We aim for 95% of requests hitting the cache within the first hour of operation.

## Consequences

Cache is lost on process restart. Not suitable for multi-instance deployments without additional coordination.
