## Decision

All API error responses use a consistent JSON envelope:

```json
{
  "error": {
    "code": "PAYMENT_DECLINED",
    "message": "The payment was declined by the issuing bank.",
    "details": {}
  }
}
```

Error codes are machine-readable strings in SCREAMING_SNAKE_CASE. HTTP status codes map to error categories (4xx for client errors, 5xx for service errors). The `details` field carries additional structured data when applicable (e.g., field-level validation failures).

## Rationale

Client integrators need machine-readable codes to implement retry logic and user-facing error messages without parsing human-readable text. A consistent envelope means a single error-handling middleware can cover all routes.

## Consequences

Every new error type must be added to the error catalogue with a code, default message, and appropriate HTTP status. Raw exceptions must never reach the response body.
