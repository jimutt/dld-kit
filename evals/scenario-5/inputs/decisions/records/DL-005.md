## Decision

All payment events (initiation, gateway response, retry, final outcome) are logged as structured JSON to stdout. Each log line includes a `correlation_id` (UUID v4, generated at request ingress and threaded through all downstream calls), a `payment_id` where applicable, a `level` (info/warn/error), and an ISO 8601 `timestamp`. No raw card numbers, full PANs, or API secrets are ever written to logs — only masked values (last 4 digits) and redacted markers.

## Rationale

Structured JSON logs are directly ingestible by log aggregation platforms (Datadog, CloudWatch) without custom parsers. Correlation IDs make it possible to reconstruct the complete lifecycle of a payment across service boundaries and retry attempts from a single query. PAN masking in the logging layer prevents accidental credential leakage even when DEBUG logging is enabled.

## Consequences

All new log statements must use the structured logger, never `console.log`. Any new sensitive field types must be added to the redaction list in the logger middleware before shipping.
