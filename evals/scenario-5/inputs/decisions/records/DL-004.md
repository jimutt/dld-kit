## Decision

Outbound requests to the payment gateway are authenticated using HMAC-SHA256 request signing. Each request includes an `X-Signature` header computed over the concatenation of the HTTP method, canonical path, UTC timestamp (ISO 8601), and request body hash. The signing key is the gateway API secret, loaded from an environment variable and never logged or serialized.

The `@PaymentGateway` integration layer handles signing transparently so application code never constructs raw gateway requests.

## Rationale

HMAC-SHA256 provides mutual authentication without transmitting credentials in the request. Including a timestamp in the signed payload prevents replay attacks within the gateway's 5-minute clock-skew window. Keeping the secret exclusively in environment variables avoids credential exposure in source control or application logs.

## Consequences

The system clock must be kept synchronized (NTP). Requests older than 5 minutes will be rejected by the gateway. Rotating the API secret requires a coordinated update of the environment variable and a service restart.
