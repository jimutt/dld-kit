## Context

The original session-cookie approach from DL-001 created problems for mobile clients and third-party integrations that couldn't easily handle cookies.

## Decision

This decision modifies part of DL-001's approach to authentication: replace session cookies with JWT bearer tokens validated on each request. Tokens are issued at `/auth/token` and expire after 24 hours.

## Rationale

JWT tokens are stateless and work uniformly across web, mobile, and API clients. Removing cookie-based auth simplifies the middleware stack.

## Consequences

- All protected endpoints must validate the `Authorization: Bearer <token>` header.
- Session storage for auth is no longer required.
- Clients must implement token refresh logic before the 24-hour expiry.
