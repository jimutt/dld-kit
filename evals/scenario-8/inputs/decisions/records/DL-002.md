# User Record Validation Rules

## Context

Now that the User data model (DL-001) is defined, we need validation logic that enforces correctness when creating or updating user records. Without explicit validation, invalid data can silently propagate through the system.

## Decision

Add a `validate_user(user: User) -> list[str]` function in `src/models.py` that returns a list of error messages (empty list means valid). Rules:

- `user_id` must be a non-empty string matching UUID v4 format (`[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}`)
- `email` must contain exactly one `@` and at least one `.` after the `@`
- `username` must be 3–32 characters, matching `^[a-zA-Z0-9_]+$`
- `created_at` must be a non-empty string (format validation is deferred to a later decision)
- `is_active` must be a boolean

## Consequences

Callers creating or updating users must invoke `validate_user` and handle any returned errors before persisting the record.
