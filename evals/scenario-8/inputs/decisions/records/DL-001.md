# User Record Data Model

## Context

We need a consistent internal representation for user records that can be shared across the authentication, profile, and notification subsystems. Different parts of the codebase have been using ad-hoc dictionaries, leading to scattered assumptions about which fields are present.

## Decision

Represent each user as a dataclass with the following fields:

- `user_id` (str): Unique identifier, UUID format
- `email` (str): Primary email address
- `username` (str): Display name, alphanumeric with underscores
- `created_at` (str): ISO 8601 timestamp of account creation
- `is_active` (bool): Whether the account is currently active

## Consequences

All subsystems will import and use the `User` dataclass from `src/models.py`. Dictionary-based user representations are deprecated.
