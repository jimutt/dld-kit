## Context

`find-missing-amends.sh` lists `<source-id>:<referenced-id>` pairs where a record's body mentions another decision ID that its `supersedes` and `amends` do not declare. The agent then judges whether each is a real modification. By default it only checks records changed since the last audit (`audit.commit_hash` in `.dld-state.yaml`), counting committed and uncommitted changes and untracked records. `--all` checks every record. It extracts the frontmatter and body with `sed` and `awk`, and only looks one directory level deep for namespaced records.

## Decision

- Records are read with the DL-014 parser. Declared IDs are `supersedes` plus `amends`. The body is everything after the closing `---` of the frontmatter.
- A candidate is every distinct `DL-<digits>` in the body that is neither the record's own ID nor declared. Output is `<source-id>:<referenced-id>`, sorted by source ID number, then referenced ID number.
- The changed-since-audit filter keeps the script's semantics:
  - It applies only without `--all` and when the audit commit is recorded, is not `unknown`, and resolves in the repository.
  - Changed means listed by `git diff --name-only <commit> -- <records dir>` (committed and working-tree changes) or untracked under the records directory.
  - If the commit is missing or unreachable, every record is checked.
- Records at any depth under the records directory are checked.

## Rationale

- Using the shared parser means the declared lists are read the same way everywhere, including the legacy-frontmatter fallback.
- The filter is what stops already-reviewed references from resurfacing every audit, so it is kept exactly.

## Consequences

- Output order becomes deterministic. Records nested deeper than one level, which the script missed, are now checked.
