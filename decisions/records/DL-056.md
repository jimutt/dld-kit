## Context

DL-002 makes the CLI (commands, flags, exit codes, and output formats consumed by skills) the public contract for 1.0, under semver. DL-011 named every ported command after the bash script it replaced (`next-id`, `collect-active-decisions`, `update-snapshot-state`, ...) and postponed renaming or regrouping until the port was complete. The port is complete, and no renames were ever planned.

Freezing all 25 commands as public at 1.0 would make every later rename a major version. Yet the skills never call a globally installed `dld`. Each skill set ships its own copy of the CLI in `dld-common/scripts/dld.mjs` (DL-035), built from the same version as the skill text, so changing a skill command cannot break an installed skill. Only people or scripts calling those commands directly could be affected, and the README documents only `init`, `update`, `install-rule` and `session-context`.

## Decision

- **Public.** The semver contract for the `dld` CLI covers the setup commands:
  - `init`, `update`, `install-rule` and `session-context`, with their flags, exit codes and documented output;
  - `--help` and `--version`.
- **Internal.** All other commands are the commands the skills run. Their names, arguments and output may change in any minor release, together with the skill templates that call them.
- **Help output.** `dld --help` lists the two groups under separate headings, "Setup commands" and "Commands the skills run (internal; may change in minor releases)". Each internal command's `--help` says the same in one line.
- **Documentation.** The README's CLI section and `docs/releasing.md` state the contract. The library API stays internal, as DL-002 says.
- **Renaming.** Regrouping the internal commands (e.g. `dld decision create`) remains possible later, without a major version. It needs its own decision.
- **Refinements during implementation.**
  - Each command the skills run sets `internal: true` in its module. The setup group lists the commands without it.
  - An internal command's `--help` appends: "Internal: the dld-kit skills run this command. Its name, arguments and output may change in a minor release."

## Rationale

- The bundled CLI makes the skill commands an implementation detail of the skills. Treating them as public would freeze bash-era names for no user benefit.
- Stating the boundary in `--help` tells anyone scripting against `dld` what they can rely on.

## Consequences

- Scripts that call internal commands directly may need changes on minor upgrades.
- Amends DL-002 (the scope of the public contract) and DL-011 (renames no longer need a major version).
