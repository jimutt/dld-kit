## Context

The bash scripts are covered by 166 bats tests, which are the behavioural specification for the port (docs/plan/v1.md). The new code needs fast unit tests, and because Bun runs the tests while Node runs production, something must prove the shipped artifact works under Node.

## Decision

Three layers, all required to pass:

1. **Unit tests** — `bun test`, colocated as `*.test.ts` beside the code they cover. They test library functions with injected dependencies (filesystem, git, clock, process execution).
2. **CLI integration tests** — run the built `dld.mjs` bundle with `node` as a subprocess against temporary git projects, asserting stdout, stderr and exit codes. These cover the command surface, not every branch.
3. **bats** — the existing suite stays until every script is ported. During the port, bats tests are pointed at `dld` subcommands; a script is removed only when its bats tests pass against the CLI. After the port the bats suite is retired, with any coverage not already in layers 1–2 moved there first.

Tests never touch the developer's real repository.

## Rationale

- Colocated bun tests keep the unit loop fast and put tests next to the code agents are changing.
- Running the bundle under Node is the only guard against Bun/Node behaviour differences and against bundling mistakes.
- Keeping bats as the oracle during the port makes the rewrite mechanically checkable, without writing a new specification.

## Consequences

- Integration tests depend on a build step first; `npm test` builds before running them.
- For a while there are three suites to keep green; that ends when the port completes.
