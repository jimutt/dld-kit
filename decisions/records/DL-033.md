## Context

`skills/` must stay committed: `npx skills`, `gh skill` and the plugin marketplaces read it straight from the repository. This repository also runs its own DLD skills from `.claude/skills/` (dogfooding), including in fresh cloud sessions, so that copy must be present after a clone. Once both are generated (DL-031, DL-032), nothing prevents a hand edit to the output or a template change without regenerating, unless the build checks it. The plan also asks that every generated file carry the version that produced it, so `dld update` can recognise stale files.

## Decision

- Both outputs are generated and committed: `skills/` with the `agent-skills` adapter, and this repository's `.claude/skills/` with the `claude-code` adapter.
- `npm run generate` regenerates both. It writes every generated file and deletes any other file under the output directories, so the generator owns them completely. It runs the TypeScript generator with Bun, a development tool (DL-001); nothing shipped depends on it.
- `npm run check:generated` generates in memory and compares with the working tree byte for byte, including file modes. It lists changed, missing and extra files and exits non-zero on any difference, telling the user to run `npm run generate`. It is part of `npm test` and runs in the CI `check` job.
- Each generated SKILL.md is stamped:
  - `metadata.dld-kit-version: <package.json version>` in the frontmatter (the Agent Skills `metadata` field);
  - an HTML comment after the frontmatter: `<!-- Generated by dld-kit from templates/skills/<skill>/SKILL.md. Do not edit; edit the template and run npm run generate. -->`.
- Supporting files (scripts) are copied without a stamp; they are replaced by the bundled CLI in workstream 7.
- CLAUDE.md and PRACTICES.md say to edit `templates/` and regenerate, never the output.

## Rationale

- Committing the Claude Code copy keeps the skills available in every checkout and exercises the adapter that `dld init` will use.
- A byte-for-byte check with extra-file detection catches hand edits, forgotten regeneration and orphaned files alike.
- Stamping only SKILL.md keeps the version where both agents and `dld update` look, without touching files that are about to be retired.

## Consequences

- Every template change produces a larger diff (template plus two outputs); reviewers read the template.
- A version bump changes every generated SKILL.md, in the release commit.
- The bats suite keeps testing the scripts under `skills/`, which are now generated copies of `templates/`.
