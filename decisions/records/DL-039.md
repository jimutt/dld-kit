## Context

DL-032 gave the `claude-code` adapter an added frontmatter line, `user_invocable: true`, to reproduce the hand-maintained `.claude/skills/` copies. Claude Code's documented field is `user-invocable` (hyphenated), and skills are user-invocable by default, so the line has no effect and suggests a setting that does not exist.

## Decision

- The `claude-code` adapter adds no `user_invocable` line. Its generated SKILL.md frontmatter is `name`, `description`, the `allowed-tools` rule for skills that run the CLI (DL-036), and the version stamp (DL-033).
- The adapter keeps its `extraFrontmatter` hook, now empty, for fields a harness genuinely needs.

## Rationale

- Generated output should only carry settings the harness reads; a no-op field misleads anyone copying the skills as an example.

## Consequences

- Every generated `.claude/skills/*/SKILL.md` loses one frontmatter line. Invocation behaviour is unchanged.
