## Context

CI reports only pass or fail. Nothing shows how well a PR's code is tested, or whether coverage dropped. The core library carries the logic (DL-007) and is covered by bun unit tests (DL-004), and Bun can write lcov coverage natively. Codecov and similar services need an account, an app install or a token. DL-005 limits the workflow's token to `contents: read`.

## Decision

- **Scope.** Coverage is measured for the unit tests over `src/` only. Test files and `src/test-helpers.ts` are excluded. The CLI tests (a bundle run under Node) and bats (bash, being retired) are not measured.
- **Configuration.** A `bunfig.toml` sets the text and lcov reporters, the output directory and exclusions. `npm run test:coverage` runs the unit tests with coverage.
- **Floor.** `coverageThreshold` is 90% for lines and 90% for functions. Bun applies it to each file, not just the total. The coverage run fails if any file is below it, which fails CI; the report still renders and flags the files below the floor.
- **PR report.** A `coverage` job:
  - runs the unit tests with coverage on the PR head;
  - runs them again on the PR's base commit (`pull_request.base.sha`), checked out in a git worktree;
  - renders totals, per-file lines and functions, and the change from base with `scripts/coverage-report.mjs` into markdown;
  - writes the markdown to the job summary;
  - posts it as a single PR comment, found by a hidden marker and updated on every push.
  If the base has no coverage setup, the report says so and shows the head only.
- **Permissions.** Only the coverage job gets `pull-requests: write`; the rest of the workflow keeps `contents: read`. The comment step is skipped for PRs from forks, whose token cannot write. The job summary still appears.
- No third-party coverage service.

## Rationale

- Unit coverage is where coverage is meaningful and cheap. Instrumenting the Node-run bundle or bash would cost far more than it tells us.
- A floor catches untested ports without being an obstacle: the skeleton is at about 99%.
- Computing the base in the same job avoids storing artifacts between runs and always compares against the actual merge base.
- A self-hosted comment needs no account or secret.

## Consequences

- The coverage job runs the unit tests twice. They take a few seconds, so this is acceptable.
- The floor can be raised later. Lowering it needs a new decision.
