## Context

DL-008 limited the `Context` filesystem interface to read operations until a ported command needed more. The commands in this slice write config, directories, records and INDEX.md. PRACTICES.md says writes that must not be seen half-finished go through a temp file plus rename. `create-config` and `create-decision` must fail if their target already exists.

## Decision

- `Context.fs` gains `writeFile`, `mkdir` (recursive), `rename`, `link` and `remove` (which ignores a missing file). The real implementation reports filesystem failures as `FsError`, a `DldError` that names the operation and path and carries the errno code (DL-012).
- Core writes files only through two helpers built on those operations:
  - `writeFileAtomic(path, content)` writes a temp file in the same directory, then renames it over the target. It is used for files that are replaced, such as INDEX.md and records edited by `update-status`.
  - `createFileExclusive(path, content)` writes a temp file, hard-links it to the target, then removes the temp file. The link fails if the target exists, which is reported as the command's "already exists" error. It is used for new files such as `dld.config.yaml` and new records.
- If a write fails, the temp file is removed. A failure to remove it is ignored, so the original error is the one reported.

## Rationale

- Temp file plus rename is atomic on POSIX filesystems when both are in the same directory, so a reader never sees a truncated INDEX.md or record.
- A hard link fails atomically when the target exists. That closes the gap between "check it doesn't exist" and "write it", and still never exposes a half-written file.
- Two named helpers make the write strategy visible at every call site and keep raw `writeFile` out of core logic.

## Consequences

- Temp files briefly appear next to their target, named `.dld-tmp-<file name>.<random suffix>`, so a crash leaves recognisable leftovers.
- Hard links need a filesystem that supports them. On one that does not (FAT/exFAT, some network mounts), `create-config` and `create-decision` fail with the filesystem's error where the scripts worked. A fallback to an exclusive open (`wx`) can be added if that turns up in practice.
