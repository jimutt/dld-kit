## Context

A timestamp ID (DL-092) says nothing to a reader, so a readable suffix on the record's file name was considered: `DL-T1k3m9z2p7xq4--retry-policy.md`. It would mean a record's path can no longer be built from its ID. Going from an annotation to its record is the most common thing agents do in a DLD project, and today it is a direct file read.

## Decision

- A record's file name is exactly `<id>.md`, for both ID forms. There is no slug in this release.
- The form `<id>--<text>.md` is reserved. `--` cannot occur in either ID form.
  - Such a file is not a record: commands that list, read or count records skip it.
  - `create-decision` and the reindex renames never write one.
  - `/dld-audit` reports every file under the records directory named this way, with the ID it appears to belong to.
- If a slug is added later it goes in the file name only. It is never part of the ID in frontmatter, annotations, `amends`, `supersedes` or mentions.

## Rationale

- Keeping path equal to ID keeps lookup trivial for agents, people and every command that matches a local record to the base branch by file name (`check-decision-edits`, `regenerate-index --include-base`, `list-proposed`).
- Reserving the syntax now keeps the later change compatible, and reporting such files stops people from adopting the form by hand before the tools read it.
- A slug inside the ID would turn renaming it into a rewrite of every annotation and reference, and make the key that programs compare ambiguous.

## Consequences

- Timestamp records show only an opaque name in directory listings and PR file lists. `INDEX.md` is where titles are.
- The later slug work has to solve lookup by ID, matching records to the base branch by ID so that changing a slug does not get around `decision_edits`, duplicate IDs under different slugs (which merge without a git conflict), stale slugs, and older CLIs that do not see slugged records. `docs/plan/timestamp-ids.md` lists them.
