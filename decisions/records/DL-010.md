## Context

`common.sh` resolves every path from `git rev-parse --show-toplevel` and fails with `not a git repository` outside git. The bats suite, which is the specification for the port (DL-004), asserts this. A config-file search walking up from the working directory is the main alternative.

## Decision

The project root is the output of `git rev-parse --show-toplevel`, run in the context's `cwd`. Outside a git repository, commands fail with `Error: not a git repository`. `dld.config.yaml` is read from the project root only.

## Rationale

- It keeps parity with the bash scripts and their tests.
- Reindex and audit need git anyway, so git is already a hard requirement.
- Running from a subdirectory resolves to the same root, which is what users expect.

## Consequences

- Nested DLD projects inside one repository (a config below the git root) are not supported. That is the existing behaviour.
- If non-git use ever matters, a config-file search can be added later as a new decision.
