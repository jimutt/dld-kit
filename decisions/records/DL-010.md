## Context

A long run overflows the context window and pi compacts, replacing older turns with an LLM-written summary. Whatever the summariser omits is gone.

For most tools that is a quality question. For DLD it is a correctness question: the point of the framework is that the reasoning behind code is preserved exactly, in the decision log. A compaction summary that paraphrases why a decision was made has manufactured a second, lossy source of truth for the one thing DLD exists to protect.

`pi-autoresearch` replaces generic compaction with a summary assembled deterministically from persisted state. Pi supports this through `session_before_compact`, where a handler may return its own summary.

## Decision

While a run is active, the extension supplies the compaction summary itself, assembled from disk rather than generated:

- The run objective, taken verbatim from `contract.md`.
- Item status: what is accepted, what is skipped, what remains, and the current item.
- The current item's decisions, quoted from their records rather than summarised.
- Recent events from `events.jsonl`, bounded.
- Open blocked questions and their answers.
- The last verification evidence for the current item.

No decision rationale is ever paraphrased. Where the summary needs a decision, it quotes the record or cites the ID for the agent to read.

When no run is active, pi's normal compaction is left alone.

## Rationale

The information is already on disk in a structured form, so summarising it with a model is strictly worse: slower, costlier, and lossy in exactly the places that matter.

Determinism also makes compaction testable. Given a state file and an event log, the summary is a pure function, which a unit test can assert against. An LLM summary can only be spot-checked.

Quoting rather than paraphrasing decisions is the whole point. An agent that reads a paraphrase of DL-012 and implements against it has done precisely what DLD is built to prevent.

## Consequences

The summary can only include what the run records. Conversation that never made it into the contract, the event log, or a decision is lost at compaction — which is an argument for recording blockers and evidence promptly, and is the behaviour the scripts already enforce.

The extension takes responsibility for a pi mechanism. If a future pi release changes compaction semantics, this handler has to keep up.

Compaction during a run and outside a run behave differently. Users may notice the discontinuity; the status line should make clear when a run is driving.
