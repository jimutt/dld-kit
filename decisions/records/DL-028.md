## Context

The reindex flow passes a rename plan between steps: `plan-renames` prints it, the agent feeds each line to `rename-decision.sh`, and pipes the whole plan into `find-stale-mentions.sh` and `commit-reindex.sh` on stdin. Each line is `<path>\t<DL-OLD>\t<DL-NEW>`. The scripts read it with `read -r` and trust it: `commit-reindex.sh` stages both the path and `<dirname>/<DL-NEW>.md` for every line, so a malformed or hand-edited plan can stage files outside the decisions directory. `rename-decision.sh` checks only that the IDs look like `DL-<digits>`, differ, and that `--path` exists.

## Decision

- The plan format is unchanged. Empty lines and lines of only whitespace are ignored; a plan with no entries counts as empty (`find-stale-mentions` prints nothing and exits 0, `commit-reindex` fails with its "no rename plan on stdin" message, as now).
- Every entry is validated before any work is done, and the first problem fails the command with an error naming the line number:
  - exactly three tab-separated fields;
  - both IDs match `DL-<digits>` and differ;
  - the path is root-relative and `/`-separated, contains no `.` or `..` segment, lies under the records directory, and its file name is `<DL-OLD>.md`;
  - no path, old ID or new ID appears twice, and no new ID is also an old ID in the same plan.
- `rename-decision`'s `--old`, `--new` and `--path` are checked with the same rules, and additionally the record at `--path` must be a regular file whose frontmatter `id` is `--old` (DL-014 parser).
- Parsing and validation live in core, shared by all three commands.

## Rationale

- `commit-reindex` stages exactly the paths the plan names; confining them to the records directory means a bad plan cannot commit unrelated files.
- Checking every line before acting keeps a half-applied plan from happening because of a typo on a later line.
- A plan produced by `plan-renames` always passes these checks, so the normal flow is unaffected.

## Consequences

- Plans that the scripts silently accepted, such as a path outside the records directory or a file whose name does not match its old ID, are rejected. The bats tests only use plans from `plan-renames`.
