## Context

`/dld-decide`, `/dld-plan` and `/dld-retrofit` tell the agent to pipe a decision's body into `create-decision` with `printf "..."`, writing `\n` for each newline. Inside double quotes the shell runs anything between backticks as a command and expands `$`, and `printf` reads `%` as a format directive. Decision bodies very often contain code in backticks, and sometimes `%` or `$`. The skills only warned about `%`. An agent in an end-to-end run noticed the backtick problem and worked around it; one that doesn't would run parts of the body as shell commands, or record a mangled body.

## Decision

- The skills pass the body to `create-decision --body-stdin` through a quoted heredoc, with real newlines:

  ```bash
  dld create-decision --id "DL-NNN" --title "..." --body-stdin <<'DLD_BODY'
  ## Context

  ...
  DLD_BODY
  ```

  The quoted delimiter turns off every expansion, so backticks, `$` and `%` reach the record as written. The skills say to keep the delimiter quoted, not to indent the body or the closing delimiter, and that no line of the body may be exactly `DLD_BODY`. The examples put the title and tags in single quotes, which are still shell strings.
- The `%%` note goes, and so does the instruction to write `\n` instead of newlines.
- `/dld-decide`, `/dld-plan` and `/dld-retrofit` change together; `create-decision` itself is unchanged.
- The skill generator enforces it: inside a template's code blocks, a `create-decision` command with `--body-stdin` (joining backslash-continued lines) fails generation if anything is piped into it or if it does not read a quoted heredoc. Prose that names the command is not checked.

## Rationale

- A quoted heredoc is the one shell construct that passes text through untouched, and it is easier for an agent to write correctly than an escaped one-line string.
- Fixing the instruction is enough: the CLI already reads the body from stdin.

## Consequences

- Bodies may now contain backticks, `$` and `%` without escaping.
- An agent whose shell has no heredocs (such as PowerShell) needs another way to pipe text into stdin; the `printf` form had the same limitation.
