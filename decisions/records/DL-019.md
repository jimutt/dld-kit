## Context

`verify-annotations.sh` and `find-annotations.sh` both grep the whole tree for `@decision(DL-NNN)`, each with its own hard-coded list of excluded directories, and the two lists differ. Both exclude the decisions directory with `--exclude-dir`, which matches only a directory's base name. A nested `decisions_dir` such as `docs/decisions` is therefore not excluded. `verify-annotations` is ported in this slice and `find-annotations` in the next.

## Decision

- Core has one annotation scanner, used by `verify-annotations` now and by `find-annotations` when it is ported.
- The file list comes from `git ls-files --cached --others --exclude-standard`: tracked files plus untracked files that `.gitignore` does not ignore.
- On top of that, one exclusion list applies. It is the union of both scripts' lists: `.git`, `.claude`, `.tessl`, `node_modules`, `vendor`, `.venv`, `__pycache__`, `target`, `dist`, `build`, `out`, `.next`, `.gradle`, `coverage`. Minified files, lockfiles and source maps are also skipped.
- The decisions directory is excluded by its full path from the project root.
- Only regular files are read, checked without following symlinks: listed paths that no longer exist (tracked files deleted from the working tree), directories (submodules) and symlinks are skipped. `Context.fs` gains `isRegularFile` for this.
- Binary files (a NUL byte in the first 8 KB) are skipped.
- The annotation is matched literally as `<annotation_prefix>(DL-<digits>)`. The prefix is not treated as a regular expression.

## Rationale

- git already knows which files belong to the project. Using its list respects the project's own ignores and avoids scanning build output that no hard-coded list anticipates.
- The hard-coded list still covers directories that are not gitignored, such as the bats fixtures' `node_modules`.
- One scanner means `verify` and `audit` can never disagree about whether an annotation exists.
- Matching the decisions directory by full path fixes the nested-directory bug.

## Consequences

- An annotation in a gitignored file no longer counts. That is intended.
- `verify-annotations` now also skips `.claude`, `coverage` and the other directories only `find-annotations.sh` excluded, so example annotations in `.claude/skills` no longer satisfy it.
- This is where configurable audit exclusions (for this repo's example annotations) will plug in, as a separate decision in the audit port.
