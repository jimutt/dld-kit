## Context

The annotation scanner (DL-019) skips a fixed set of directory names wherever they appear: `.git`, `.claude`, `.tessl`, `node_modules`, and so on. `.claude` is there so the Claude Code skills' own `@decision(DL-NNN)` examples never count as annotations.

Since 1.0, skills also install into other agents' directories:

- `dld init` and `npx skills` install into `.agents/skills/`.
- `npx skills` also installs into `.pi/skills/` and others.
- `dld init` writes `.agents/rules/` for Antigravity.

Testing `1.0.0-rc.2` in a project set up for Claude Code and OpenCode found 11 false annotations from `.agents/skills/`, reported by `find-annotations` and therefore by dld-audit, while `.claude/skills/` was correctly skipped. The tester worked around it with `annotation_exclude` (DL-023).

## Decision

- The built-in exclusion list adds the configuration directories of the agents dld-kit installs for, or that the skill installers write to:
  - `.agents` (the shared skills and rules directory, used by Codex, Cursor, OpenCode, Antigravity and Pi)
  - `.agent` (older Antigravity)
  - `.codex`
  - `.cursor`
  - `.opencode`
  - `.pi`
- As with `.claude`, a directory with one of these names is skipped wherever it appears in a path. `annotation_exclude` stays available for anything else.
- A test covers annotation examples in installed skills under each of these directories, and checks that `find-annotations` and `verify-annotations` ignore them.

## Rationale

- These directories hold agent configuration and installed skills, not project code, just like `.claude`. Excluding them by name matches the existing rule, and needs no configuration in each project.

## Consequences

- A project that keeps real code inside one of these directories would have to rename it; this is accepted as unlikely.
- Amends DL-019 (the exclusion list).
