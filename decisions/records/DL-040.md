## Context

DL-035 makes a globally installed `dld` (npm) the entry point for people, CI and project setup, but the CLI has no setup commands yet. Today a project is set up by the dld-init skill, which runs `create-config`, `create-directories` and `create-empty-index` and then writes a CLAUDE.md block by hand; the skills themselves arrive by copying or through `npx skills`. Workstream 8 of `docs/plan/v1.md` adds `dld init` and `dld update` so npm users get the decision log, the skills and the always-on rule in one step, and can refresh them after upgrading.

## Decision

- `dld init [--namespaces <a,b,...>] [--agent <names>] [--yes]` sets up DLD in the current git repository:
  - It fails (exit 1) if `dld.config.yaml` already exists, telling the user to run `dld update`.
  - It creates `dld.config.yaml` (flat, or namespaced when `--namespaces` is given), the decisions directories and an empty INDEX.md, through the same library functions as `create-config`, `create-directories` and `create-empty-index`.
  - It installs the skills (DL-042, DL-043) and the always-on rule (DL-045) for the selected harnesses (DL-041).
  - It does not write PRACTICES.md: that takes judgment and conversation, and stays with the dld-init skill.
  - It prints every path it created or changed, then the next steps (`/dld-retrofit` for existing code, `/dld-decide` otherwise).
- `dld update [--agent <names>] [--force]` refreshes an initialised project:
  - It fails if `dld.config.yaml` does not exist, telling the user to run `dld init`.
  - It regenerates the skills in every skills directory that already holds `dld-*` skills and every rule channel already installed, plus those of harnesses named with `--agent`.
  - If nothing is installed and no `--agent` is given, it fails and lists the harness names.
  - It never touches `dld.config.yaml`, decision records, INDEX.md or PRACTICES.md.
  - It prints, per location, how many files were written, removed and left unchanged.
- Both are ordinary `dld` commands: `--help`, strict argument parsing (DL-017) and the error and exit-code conventions of DL-012. They are new commands, not script ports, so DL-011's naming rule does not apply.
- The logic lives in library code (`src/core` or `src/generate`) that returns what to write; the command modules only parse arguments, prompt and print (DL-007).

## Rationale

- One command that does everything the skill does mechanically, plus installing the skills, gives npm users a working project without an agent session.
- Refusing to re-run `init` keeps it from overwriting a configuration; `update` is the one command for everything after setup, including the move from pre-1.0 copies (DL-043).
- Keeping PRACTICES.md in the skill follows PRACTICES.md: judgment and user interaction belong in skills, mechanics in code.

## Consequences

- The dld-init skill and `dld init` overlap on the config, directories and index; both call the same library code, so they cannot drift.
- `dld update` becomes the documented upgrade step for npm users (workstream 10).
