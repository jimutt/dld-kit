## Context

The 1.0 plan distributes the skills through a Claude Code plugin marketplace, reviving PR #23 (May 2026). That PR put `.claude-plugin/plugin.json` and `marketplace.json` at the repository root and let the plugin load the root `skills/`. Since then the skills are generated per adapter (DL-032, DL-036). The root `skills/` now holds the portable variant, which writes commands as `node "<skill-dir>/../dld-common/scripts/dld.mjs"`. The claude-code variant writes the exact `${CLAUDE_SKILL_DIR}` path and adds an `allowed-tools` rule for it. The claude-code variant is also what `dld init --agent claude` installs (DL-040).

How Claude Code handles plugins (September 2026):

- **Marketplace.** `.claude-plugin/marketplace.json` requires `name`, `owner` and `plugins[]`. Each entry needs `name` and `source`, which may be a relative path starting with `./` inside the same repository.
- **Installation.**
  - An installed plugin is copied into `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`. Nothing outside the plugin directory is copied.
  - Its skills are found at `<plugin>/skills/<name>/SKILL.md`.
  - A skill is invoked as `/<plugin>:<skill>`, or bare when the name is unique.
  - `${CLAUDE_SKILL_DIR}` and `${CLAUDE_PLUGIN_ROOT}` are substituted in plugin skills.
- **Versioning and updates.**
  - The version comes from `plugin.json`, else the marketplace entry, else the git commit.
  - Third-party marketplaces do not auto-update by default.
- **Copilot CLI** also reads `.claude-plugin/marketplace.json`, after its own locations (DL-050).

## Decision

- **The marketplace.**
  - `.claude-plugin/marketplace.json` at the repository root declares the marketplace `dld-kit`, with owner, description and one plugin entry.
  - The entry is named `dld`, with `source: "./claude-plugin"`, a description, category and tags.
  - Users install with `/plugin marketplace add jimutt/dld-kit` and `/plugin install dld@dld-kit`. Skills run as `/dld-plan`, or `/dld:dld-plan` when another skill has the same name.
- **`claude-plugin/` is generated output**, committed and drift-checked like `skills/` (DL-033). It holds:
  - `.claude-plugin/plugin.json`: name `dld`, version, description, author, homepage, repository, license, keywords. There is no `skills` field; the default `skills/` discovery applies.
  - `skills/`, rendered by the claude-code adapter, including `dld-common/scripts/dld.mjs` (DL-035). dld-common has no SKILL.md in that adapter, so it appears neither in the menu nor in the model's context.
  - `hooks/hooks.json`, the rule hook (DL-049).
- **Generation.**
  - `scripts/generate.ts` writes `claude-plugin/` and `.claude-plugin/marketplace.json`, and `npm run check:generated` fails when either differs.
  - Manifest fields (description, author, homepage, repository, license, keywords, version) are rendered from `package.json`, so they cannot disagree (DL-052).
- **Exclusions.**
  - `claude-plugin/**` is added to this repository's `annotation_exclude` (DL-023), like `skills/**`, and to any lint exclusion `skills/` has.
  - It is not part of the npm package.
- **Real copies, not symlinks.** Every generated `dld.mjs` stays a full copy.
  - `gh skill install` skips symlinks, and `npm pack` leaves them out of the tarball, so `skills/` must hold the real file.
  - Claude Code copies a symlink's target into the cache only for marketplace installs from a repository. It skips such links for plugins installed from a local path, which is the usual way to test the plugin.
  - Windows checkouts without symlink support, and a plain `cp -r` of `.claude/skills/dld-*`, would break the dogfooding copy.
- **Collapsed diffs.** A `.gitattributes` file marks the generated paths `linguist-generated`, so GitHub collapses them in pull request diffs: `skills/`, `.claude/skills/`, `.claude/rules/`, `claude-plugin/` and the generated manifests.
- **PR #23** is closed as replaced by this decision.

## Rationale

- Rendering the plugin with the claude-code adapter gives Claude Code the same skill text whichever channel installed it: exact commands, and a pre-approvable CLI path.
- A subdirectory keeps the plugin cache to the plugin itself rather than a copy of the whole repository.
- Generating the manifests from `package.json` removes a second place to bump versions and metadata.
- The name `dld` keeps PR #23's choice and the short qualified form `/dld:dld-plan`.

## Consequences

- A third committed copy of `dld.mjs` (about 330 KB) changes with every change under `src/`. Git stores identical content once, so history grows by one blob per CLI change, not three. Only the working tree holds the extra copies.
- A user with the plugin, working in a project that also has dld-kit skills in `.claude/skills/`, sees each skill twice. The README tells users to pick one channel per project.
- The skill installers must not pick up `claude-plugin/skills/` as a second copy of the skills; DL-051's installer check covers that.
