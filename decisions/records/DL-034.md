## Context

The 1.0 plan drops Tessl as a distribution channel (docs/plan/v1.md, "Distribution"). The repository still carries its packaging: `.tessl-plugin/plugin.json`, `.tesslignore`, the steering rule in `rules/dld-workflow.md` (listed in the plugin and in `package.json` `files`), the note in dld-init that Tessl users can skip the CLAUDE.md step, the "Tessl packaging" and "Dual directory layout" sections of CLAUDE.md, and the Tessl install instructions in the README. With the generator (DL-031 to DL-033), the dual directory is no longer maintained by hand.

How the always-on rule reaches users after Tessl (a managed block, a hook, or both) is its own decision in workstream 8.

## Decision

- Delete `.tessl-plugin/` and `.tesslignore`.
- Move the steering rule's text to `templates/rules/dld-workflow.md` as the canonical rule text. No output is generated from it yet, and `rules/` is removed from `package.json` `files`; workstream 8 decides how it is delivered.
- Remove the Tessl note from the dld-init template.
- Replace the "Dual directory layout", "Tessl packaging" and "Shell scripts" guidance in CLAUDE.md with a description of `templates/` and the generated outputs, and update the Skills section of `decisions/PRACTICES.md` to match. The "run `tessl plugin lint`" convention is removed.
- Remove the README's Tessl install instructions and point Claude Code users at the generated skills until the channels in workstream 9 exist; the full install documentation is workstream 10.
- `templates/**` is added to this repository's `annotation_exclude` (DL-023), since templates contain example annotations.
- `.tessl` stays in the annotation scanner's excluded directories (DL-019): user projects may still contain it.

## Rationale

- Keeping packaging for a dropped channel invites edits to files nothing reads, and the Tessl lint step was the only check on skill structure; the generator's validation (DL-031) replaces it.
- Moving the rule text instead of deleting it keeps the content for workstream 8 without shipping it through a channel that no longer exists.

## Consequences

- Existing Tessl users stop receiving updates; migration notes are part of workstream 10.
- Until workstream 8, no channel ships the always-on rule; dld-init still writes the CLAUDE.md instructions.
