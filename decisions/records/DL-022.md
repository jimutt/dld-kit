## Context

The OpenCode spike produced three copies of `parseStartArgs`, two ad-hoc state readers with unjustified casts, and a widget-window bug that `render.ts` had already solved. The quality review's B1 recommended extracting shared modules. The direction document (docs/plan/typescript-core.md) frames the extraction as Move 1 toward an npm package: the shared module's API is the future package's public API.

## Decision

Create `extensions/dld-core/` as a TypeScript-native library. Its API is function-shaped and typed; it exposes no script paths, no argv arrays, no exit codes.

**Reads** (pure, no subprocess):
- `readRunState(runDir)` / `readRunEvents(runDir)` — moved from `run-state.ts`, with shape validation
- `activeMinutes(state, events)` — moved from `run-state.ts`
- `statusLine(state)` / `widgetLines(state)` / `boardLines(state)` — moved from `render.ts`
- `parseStartArgs(tokens)` — extracted from the Pi index.ts, taking `string[]`

**Mutations** (delegating to the bash scripts for now):
- `createRun(root, slug, title)` / `addItem(root, slug, decisionIds)` / `setRunStatus(root, slug, status)` / `setItemStatus(root, slug, index, status)` / `repinItem(root, slug, index)` / `appendRunEvent(root, slug, type, data?)` / `blockItem(root, slug, index, reason)` / `verifyItem(root, slug, index)` / `nextItem(root, slug)` / `activeRun(root)` / `resumableRun(root)` / `guardPreconditions(root, mode, args)`

Each mutation returns a typed result: `{ ok: true, value? } | { ok: false, error }`. No caller interprets exit codes or stream contents. Timeout/buffer policy (verify gets 300s/16MB, SIGTERM is infrastructure not failure) lives inside the module.

**Path resolution** is existence-checked: `packageRoot()` walks up from the module's own URL until it finds `skills/dld-run/scripts/`, failing loudly via `missingScripts()` rather than assuming a directory depth.

Both extensions migrate to the library. The Pi extension keeps its async `pi.exec` behind the same function signatures (the mutations take an injected exec); the OpenCode plugin uses the default sync `execFileSync` implementation. The exec is an injectable dependency, not part of the API surface.

## Rationale

A function-shaped API is what makes the strangler-fig work: when the scripts are rewritten as TypeScript (Move 2), the function bodies change and no caller notices. An API that leaks script paths or exit codes would bake the bash implementation into every caller.

The injectable exec is the seam that lets pi keep its sandboxed async execution while OpenCode uses direct child processes — same functions, different substrate, no duplicated logic.

Pi ignores `extensions/` subdirectories without an `index.ts`, so `dld-core` is invisible to pi's loader. OpenCode imports files directly. No build step; TypeScript source ships.

## Consequences

`extensions/dld-run/` loses `paths.ts`, `run-state.ts`, `render.ts`, and its `parseStartArgs` — all imports redirect to `../dld-core/`. `render.test.ts` moves with `render.ts`; a new `parse-start-args.test.ts` covers the parser. The OpenCode plugin deletes ~200 lines of duplicated logic and its partial `RunState` interfaces.

The `widgetLines` 5-line invariant and its test coverage now protect both harnesses.

The bash scripts remain the mutation implementation. Nothing about the skills, the run contract, or the dual-copy layout changes in this move.
