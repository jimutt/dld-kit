## Context

`find-annotations.sh` greps the tree for lines containing an annotation and then prints `<file>:<line>:<ID>` for **every** `DL-NNN` on each matching line, including IDs that are not themselves annotations (e.g. `// @decision(DL-001) replaces DL-005` also yields DL-005). DL-019 created one core scanner, used by `verify-annotations`, for exactly this job.

## Decision

- `dld find-annotations` prints the shared scanner's results as `<file>:<line>:<DL-NNN>`, one line per annotation, with paths relative to the project root and `/` separators. Output is sorted by file, then line, then position on the line. No annotations means no output and exit 0.
- Only IDs inside an annotation (`<prefix>(DL-NNN)`) are reported. Plain `DL-NNN` mentions on the same line are not.
- It inherits the scanner's file selection (DL-019): gitignored files are skipped, and so are paths excluded by configuration (DL-023).

## Rationale

- Reporting plain mentions made `/dld-audit` treat prose such as "replaces DL-005" as a code reference to DL-005, which is a false positive the audit then has to explain away.
- Sharing the scanner guarantees `find-annotations` and `verify-annotations` always agree.

## Consequences

- Intended differences from the script: plain mentions on annotated lines are no longer reported, gitignored files are no longer scanned, and output order is deterministic.
