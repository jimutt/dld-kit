## Context

`dld init` and `dld update` (DL-040) render the skills with `generateSkills` (DL-032) and must ship the bundled CLI inside `dld-common` (DL-035). The npm package today ships `dist/dld.mjs` and the pre-rendered `skills/`, but not `templates/`, so an installed CLI cannot render the claude-code layout or a rule. The same `dld.mjs` also ships inside every skill set, where it runs the mechanical commands.

## Decision

- The package `files` allowlist adds `templates/skills/` and `templates/rules/`. `npm run check:pack` asserts they are included.
- `dld init` and `dld update` find the templates relative to the running CLI file: `<directory of dld.mjs>/../templates/`, which is `templates/` in the npm package and in a dld-kit checkout. `bin.ts` resolves the file from `import.meta.url` and passes it to commands as `Io.cliPath`; library code receives it as an argument, so core stays free of `process` (DL-007).
- The CLI copies its own file into the output as `dld-common/scripts/dld.mjs` (DL-035's `extraFiles`), so a project's skills carry exactly the CLI version that installed them, and their version stamps match it.
- A CLI copy with no templates beside it (the one inside `dld-common`) fails `init` and `update` with an error naming the npm route, e.g. `npx dld-kit@latest init`.
- The rule text (`templates/rules/dld-workflow.md`) is imported as a string with `import ... with { type: "text" }`, which both esbuild (the bundle) and Bun (tests, `npm run generate`) inline, so every copy of the CLI, including the one inside `dld-common`, can install the rule (DL-045).

## Rationale

- Rendering at install time keeps one generator path, which is what DL-032's in-memory output was designed for, and lets the output depend on the project (which harnesses, where the rule goes).
- Embedding all templates (about 87 KB) in the bundle would let the bundled copy run `init`, but would add that weight to every installed skill set for a command skill-channel users do not need. The rule text is small, and the dld-init skill needs it.
- Copying the running file avoids a second bundle in the package and guarantees the installed CLI matches the stamps.

## Consequences

- DL-002's allowlist, "built output, skills, and docs", now includes template sources. They are plain markdown, not tests or development configuration.
- The package grows by the size of the templates.
