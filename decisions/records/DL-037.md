## Context

The bash scripts under `templates/skills/*/scripts/` are all ported (workstreams 3 to 5). The bats suite (about 160 tests) was the behavioural oracle for the port: DL-013 runs it against the scripts and, through a shim built from `tests/cli-ported.txt`, against the CLI. Once skills call the CLI (DL-035, DL-036), nothing runs the scripts, and the oracle has nothing left to compare. The bats suite, its `tests/bats` submodule, the shim (`scripts/bats-cli.mjs`), `tests/cli-ported.txt`, `tests/run.sh` and the CI bats matrix only exist for the port. PRACTICES.md says a script is removed only after its behaviour is covered by the CLI's tests.

## Decision

- Delete every script under `templates/skills/*/scripts/` (and so from both generated outputs), including `common.sh`. `dld-common` keeps only its SKILL.md and the bundled `dld.mjs`.
- Before deleting the bats suite, audit it: map each bats test to a bun test (unit or `tests/cli`) that covers the same behaviour. Port every gap as a bun test first. The mapping is reported in the implementing PR.
- Tests that only check the scripts themselves (shell strict mode, shebangs, `common.sh` helpers with no CLI equivalent) are dropped with the scripts. The structure checks on generated SKILL.md files (references exist, frontmatter fields) are covered by the generator's validation (DL-031) and `check:generated` (DL-033); any check they do not cover is ported to a bun test.
- Delete `tests/bats` (submodule and `.gitmodules` entry), `tests/test_*.bats`, `tests/test_helper/`, `tests/run.sh`, `tests/cli-ported.txt`, `scripts/bats-cli.mjs`, the `test:bats` and `test:bats:cli` npm scripts and the CI bats job.
- This supersedes DL-013.

## Rationale

- Keeping a second test framework, a submodule and a bash dependency for code that no longer ships costs every contributor setup time and CI minutes for no coverage.
- The audit keeps the promise that removing the oracle loses no behavioural coverage.

## Consequences

- The test layers become: unit tests, CLI integration tests, and the generated-output check. Bash is no longer needed to develop or test dld-kit.
- Future behaviour changes are specified in bun tests only.
