## Context

DL-019 has the annotation scanner read every file git lists, tracked or untracked but not ignored, as one UTF-8 string, and only then sniff its first 8 KB for a NUL to skip binaries. A large untracked file, such as a downloaded multi-GB archive, makes the read throw ERR_STRING_TOO_LONG past V8's string limit (about 512 MB). The error was not caught per file, so `verify-annotations` and `find-annotations` failed outright until the file was moved or excluded (issue #89). Large binaries under the limit were also read whole just to be skipped.

## Decision

- Files larger than 16 MB are skipped without being read. The cap is a constant (`MAX_SCAN_BYTES`), not a config key.
- `Context.fs` gains `fileSize`, which reads the size without following symlinks, so the check happens before the read.
- A listed file that fails to read (any `FsError`, including ERR_STRING_TOO_LONG and EACCES) is skipped instead of aborting the scan. Other errors still propagate, since they are bugs.
- Skipped files are reported, not dropped silently: `scanAnnotations` and `missingAnnotations` take an optional `onSkip` callback, and `verify-annotations` and `find-annotations` print one line per skipped file on stderr: `Warning: skipped <file> (<reason>); annotations in it are not counted`. Stdout and exit codes are unchanged.
- Binary files are still skipped silently, as DL-019 says.

## Rationale

- Annotations live in source files; a source file over 16 MB is almost certainly generated or data, and reading it into memory only to skip it is waste.
- A size check from `lstat` is cheap and needs no new read path; with the cap, a skipped file is never loaded, and a file under the cap costs at most 16 MB of memory.
- One unreadable file should not block the annotation check for the whole project. Reporting it on stderr keeps a possible false MISSING explainable.
- A config key for the cap was left out until someone needs it; `annotation_exclude` (DL-023) already covers files that should not be scanned at all.

## Consequences

- An annotation in a file over 16 MB, or in an unreadable file, no longer counts. The warning names the file.
- `rename-decision` and `find-stale-mentions` still read changed files whole; they only see files changed since the merge-base, so the issue is far less likely there, but they are not covered by this decision.
