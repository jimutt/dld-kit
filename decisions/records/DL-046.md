## Context

OpenCode reads skills from both `.claude/skills/` and `.agents/skills/`. When a skill name appears in both, which copy it loads is effectively nondeterministic. A project that installs dld-kit for Claude Code and for an `.agents/skills/` harness (DL-041) therefore gives OpenCode two copies of every skill. The claude-code copy writes its commands with `${CLAUDE_SKILL_DIR}` (DL-036), which only Claude Code substitutes. OpenCode instead tells the agent the skill's base directory, but nothing links the two.

OpenCode also runs skill bodies through its command templating. It substitutes `$ARGUMENTS`, `$1` to `$n` and `` !`cmd` `` (shell output). No template uses these today, but a future one could.

## Decision

- The claude-code adapter's `{{dld-setup}}` text starts by defining the variable: "`${CLAUDE_SKILL_DIR}` is the absolute path of this skill's directory."
  - Claude Code substitutes it, so the sentence reads as a true statement about the path.
  - A harness that does not substitute it can resolve the variable from the base directory it reports.
- The generator rejects template text that another harness's skill loader rewrites: `$ARGUMENTS`, `$` followed by a digit, and `` !` ``. The error names the template and line. The check covers code blocks too, since loaders do not distinguish them.

## Rationale

- One sentence makes the Claude copy usable wherever it is read, which is simpler than trying to prevent OpenCode from seeing both directories. OpenCode's `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS` switch is left to the docs.
- Failing at generation catches the templating hazard before a skill silently loses text in one harness.

## Consequences

- Amends DL-036 (the claude-code setup text) and DL-031 (template validation).
