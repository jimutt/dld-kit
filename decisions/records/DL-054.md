## Context

DL-045 installs the rule once per harness. Claude Code gets no owned rule file when it already reads the managed block, which DL-045 describes as "the block is in CLAUDE.md, or in AGENTS.md with no CLAUDE.md". DL-049 gave each harness an ordered `instructions` list: Claude Code `[CLAUDE.md, AGENTS.md]`, Pi and OpenCode `[AGENTS.md, CLAUDE.md]`, the others `[AGENTS.md]`. It resolves the file a harness reads as the first entry that exists, else the last entry.

Testing `dld-kit@1.0.0-rc.1` in another repository (`init --yes --agent claude,opencode` with neither instruction file present) showed two problems:

- **A self-contradictory OpenCode warning.** The block is planned into a new AGENTS.md. Because that file does not exist yet, OpenCode resolves to its last entry, CLAUDE.md, and is reported as unable to see the block: "The dld-kit rule block is in AGENTS.md, but OpenCode reads AGENTS.md. To cover it, move the block … into AGENTS.md". The message also hardcodes AGENTS.md rather than naming the file the harness reads.
- **Claude Code's reading of AGENTS.md is fragile.** Claude Code's memory documentation (September 2026) confirms that it reads AGENTS.md only when there is no CLAUDE.md, `.claude/CLAUDE.md` or `CLAUDE.local.md` in the working directory or above it. It also needs Claude Code v2.1.277 or later, and some sessions cannot read AGENTS.md. `.claude/rules/` files load in every case. dld-kit only checked CLAUDE.md. A developer with a local `CLAUDE.local.md`, or a team that later adds `.claude/CLAUDE.md`, got no rule in Claude Code, and nothing said so.

Writing `.claude/rules/dld-workflow.md` in every case would remove the fragility. But in a repository with only AGENTS.md, Claude Code would then load the rule twice in every session for every developer, and the project owner ruled that out.

## Decision

- **Claude Code's instruction list follows its documentation:** `[CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md, AGENTS.md]`. A harness reads the first entry that exists. Claude Code therefore reads the block in AGENTS.md only when none of the three CLAUDE files exists. Otherwise it gets `.claude/rules/dld-workflow.md`, and the plugin hook (DL-049) counts it the same way.
- **Planned files count as existing.** When `planRule` resolves the file a harness reads, a file that will receive the block counts as existing. When no listed file exists, the harness reads nothing, and there is no fallback to the last entry.
- **The warning names the real file.** It says which file each harness reads: "The dld-kit rule block is in CLAUDE.md, but Codex reads AGENTS.md …". A harness that reads no instruction file at all is reported as reading its first entry, which is where the block would have to go.
- **A note when Claude Code relies on AGENTS.md.** When Claude Code is among the harnesses, reads the block from AGENTS.md, and the plan writes the block, init and install-rule print a note. It says that adding a CLAUDE.md, `.claude/CLAUDE.md` or `CLAUDE.local.md` later stops Claude Code from reading AGENTS.md, and that `dld update` or `dld install-rule` then installs `.claude/rules/dld-workflow.md`. The note goes out with the warnings.
- **The README says where Claude Code's rule goes:** `.claude/rules/dld-workflow.md`, unless Claude Code already reads the block in AGENTS.md.
- **Once per harness stays:** the rule is never written twice for Claude Code.
- **Parent directories are not checked.** Claude Code also counts CLAUDE files above the working directory. dld-kit installs per project, so it only looks at the project root.

## Rationale

- Following Claude Code's documented rule avoids both loading the rule twice and silently losing it for developers who have a `CLAUDE.local.md`.
- Resolving against the planned block removes an ordering accident: the same fallback pointed Claude Code and OpenCode at opposite files.
- The note makes the one remaining fragile case, a CLAUDE file added after init, visible at the moment it is set up.

## Consequences

- A developer who adds a CLAUDE file after init still has to run `dld update` or `dld install-rule`. The note, the README and DL-043's `update` behaviour cover this.
- Amends DL-045 (which files Claude Code reads) and DL-049 (the `instructions` lists and their resolution).
