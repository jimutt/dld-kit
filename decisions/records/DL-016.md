## Context

OpenCode is a client/server AI coding agent with a V2 beta plugin API that includes TUI widgets. The Pi extension proved the dld-run concept: state in files, loop via agent_end dispatch, layered UI. Porting to OpenCode validates that the design is harness-agnostic and reaches users who prefer OpenCode's open-source model.

The research identified three viable shapes: external driver (works on V1, most stable), V1 plugin loop (degraded UX), and V2 combined plugin (best fit, least stable). The V2 combined plugin is the only shape that supports the full dld-run UI surface.

## Decision

Build the OpenCode dld-run as a V2 combined plugin with two entrypoints: a server plugin (`src/index.ts`) holding the loop controller, state reader, and script execution; and a CLI plugin (`src/tui.tsx`) holding the UI surfaces (status line, widget, board). The two communicate through the server's event stream and the filesystem.

The spike validates the riskiest unknowns: process split, continuation dispatch via `session.prompt`, exec semantics via `Bun.$`, and state sharing between server and CLI. The full implementation adds the complete UI surface.

## Rationale

The process split is architectural — OpenCode's client/server model forces it. The server plugin owns the agent loop position and filesystem access; the CLI plugin owns the TUI. They cannot be one process, and they may not even be on the same machine.

The communication channel question was resolved during the spike: the CLI plugin reads `.dld/runs/` from disk directly, same as the server plugin. `ctx.storage` is server-only and doesn't bridge to the CLI. This means the plugin is local-only for v1 — a CLI connected to a remote server can't read the workspace's `.dld/` directory. Acceptable for the spike; a remote-capable version would need the server plugin to expose state through a custom tool or event.

## Consequences

Two packages in one, or one package with two entrypoints. The server plugin registers commands and tools; the CLI plugin registers slots, dialogs, and keymaps. The loop controller and render logic are shared — imported by both, or duplicated if the packaging doesn't support shared modules.

V2 is beta. Contracts may break. The plugin pins to a specific `@opencode-ai/cli` version and documents the pin.
