## Context

The reindex flow starts with four read-only scripts:

- `resolve-base.sh` prints the branch's upstream when it tracks a differently named branch, and `origin/main` otherwise. It does not read `dld.config.yaml`.
- `list-taken-ids.sh [--base <ref>]` prints the IDs taken on the base branch (every `DL-<digits>` in `git ls-tree -r --name-only <base> -- <records dir>`) and in open PRs (DL-026), sorted with `sort -u`.
- `find-collisions.sh [--base <ref>]` prints `<path>\t<DL-NNN>` for each record added on the branch (`git diff --name-only --diff-filter=A <base>...HEAD -- <records dir>`) whose file name is `DL-<digits>.md` and whose ID is taken.
- `plan-renames.sh [--base <ref>]` sorts the collisions and assigns each the next ID above the highest taken or locally added ID, printing `<path>\t<DL-OLD>\t<DL-NEW>`.

The scripts call each other, so `plan-renames.sh` runs `list-taken-ids.sh` twice and can print the open-PR notice twice. It sorts collisions with `sort -t$'\t' -k2,2`, a text sort that puts `DL-1000` before `DL-999`. All default the base to `origin/main`.

## Decision

- The four become `dld resolve-base`, `dld list-taken-ids`, `dld find-collisions` and `dld plan-renames` (DL-011), backed by one core module. Taken IDs, local additions and collisions are computed once per command, so `gh` runs at most once and the notice prints at most once. When the branch adds no records, the open-PR scan is not run at all.
- `resolve-base` keeps the script's logic and, like the script, works without `dld.config.yaml` and prints `origin/main` when git cannot answer.
- The default base stays `origin/main`. A base that starts with `-` is a usage error. A base that does not resolve to a commit fails with the script's message (`list-taken-ids` keeps its "Fetch first or pass --base." suffix).
- Paths from git are read with `-z` (DL-024), so records under non-ASCII paths are found.
- `list-taken-ids` output is sorted by ID number rather than as text.
- `plan-renames` orders collisions by ID number, then path. New IDs start at one above the highest ID taken or added locally (0 if none), increase by one, and are formatted with `formatId` (DL-014), so they keep at least three digits.
- Output formats are unchanged: tab-separated fields, one entry per line, nothing when there is nothing to report.

## Rationale

- Computing once removes the repeated gh calls and the duplicated notice without changing what the commands report.
- Numeric ordering only matters past `DL-999`, where the text sort gives a plan that assigns IDs in a surprising order; the sets of IDs are the same.

## Consequences

- The skills keep calling the same four operations with the same arguments and output.
- Changing the default base (for example to `origin/HEAD`) is left for a later decision.
