## Context

DL-045 places a new rule block in AGENTS.md if it exists, else in CLAUDE.md if it exists, else in a new AGENTS.md. The middle step rests on its claim that "Pi and OpenCode read AGENTS.md, falling back to CLAUDE.md when there is none". DL-054 gave each harness a list of instruction files and resolved the one it reads as the first that exists: Cursor `[AGENTS.md]`, OpenCode and Pi `[AGENTS.md, CLAUDE.md]`.

Two findings show this is wrong:

- **The 0.x upgrade check (DL-057).** Every 0.x project has a CLAUDE.md, because the old dld-init appended its DLD section to it, and usually no AGENTS.md. `dld update --agent claude,codex` therefore puts the block into CLAUDE.md, which Codex does not read, and warns that Codex cannot see it (DL-054). The README currently works around this by telling users to create an empty AGENTS.md first.
- **A fact-check of the harness docs (September 2026):**
  - **Cursor.** Cursor reads CLAUDE.md "the same way it reads AGENTS.md", and applies it to every conversation (cursor.com/help/customization/rules). It reads both files when both exist, not the first of them. dld-kit's warning that Cursor cannot see a block in CLAUDE.md is false.
  - **OpenCode.** OpenCode 2.x discovers only AGENTS.md; its migration guide tells users who relied on the CLAUDE.md fallback to move that guidance into AGENTS.md (opencode.ai/v2/docs/migrate-v1). A block that dld-kit puts into CLAUDE.md for OpenCode is never read. dld-kit supports OpenCode 2.x only; the 1.x fallback is not modelled.
  - **Pi** still reads AGENTS.md, else CLAUDE.md, in each directory.

## Decision

- **Instruction files per harness** (amends DL-054's lists):
  - Cursor reads every file of `[AGENTS.md, CLAUDE.md]` that exists. A harness can now be marked as reading all of its list rather than the first match; Cursor is the only one.
  - OpenCode reads `[AGENTS.md]`.
  - Pi keeps `[AGENTS.md, CLAUDE.md]`, first that exists. Codex and Antigravity keep `[AGENTS.md]`. Claude Code keeps DL-055's model.
- **Placement of a new block** (amends DL-045), when no AGENTS.md or CLAUDE.md holds a block yet:
  1. AGENTS.md, if it exists.
  2. Else CLAUDE.md, if it exists and every harness the block is being installed for reads CLAUDE.md when there is no AGENTS.md. That is Cursor and Pi.
  3. Else a new AGENTS.md. This covers the 0.x upgrade (`--agent claude,codex`) and any CLAUDE.md-only project set up for Codex, OpenCode or Antigravity.
- **Claude Code** is unaffected. With the block in a new AGENTS.md beside an existing CLAUDE.md, Claude Code gets `.claude/rules/dld-workflow.md`, as DL-055 already plans, so each harness loads the rule once.
- **A warning for Pi.** When dld-kit creates AGENTS.md next to an existing CLAUDE.md and Pi is among the harnesses being installed, it warns that Pi now reads AGENTS.md instead of CLAUDE.md, so anything Pi needs from CLAUDE.md must move into AGENTS.md.
- **Existing blocks** are still refreshed where they are (DL-045). A block already in CLAUDE.md still gets DL-054's warning for the harnesses that cannot see it, which now includes OpenCode and no longer includes Cursor.
- **Docs.**
  - The README drops the `touch AGENTS.md` step from "Upgrading from 0.x".
  - Its Agents section describes the new placement, Cursor reading both files, and OpenCode reading only AGENTS.md.
- **Tests.**
  - Unit tests cover the placement for Codex, Cursor, OpenCode and Pi alone and combined, in projects with CLAUDE.md, AGENTS.md, both or neither, including the Pi warning.
  - They also cover Cursor reading a block in either file (no warning), and OpenCode being warned about a block in CLAUDE.md.
  - The 0.x upgrade CLI test runs `update --agent claude,codex` without creating AGENTS.md first, and expects the block in AGENTS.md and only the old-section warning.

## Rationale

- A block in a file one of its target harnesses never reads is a broken install. The warning only reports it after the fact.
- The CLAUDE.md fallback stays for the harnesses that still read CLAUDE.md, in projects whose instructions live there.
- The 0.x upgrade is the most common path into 1.0 for existing users, and nearly all of them have a CLAUDE.md.
- Modelling only OpenCode 2.x keeps the table to one behaviour per harness. For 1.x users the result is still correct, because a block in AGENTS.md is what 1.x reads first.

## Consequences

- Installing for Codex, OpenCode or Antigravity in a CLAUDE.md-only project now creates AGENTS.md.
- A project that uses Pi without naming it in `--agent` gets no warning when AGENTS.md is created, and Pi switches to reading AGENTS.md.
- An OpenCode-only project with an existing block in CLAUDE.md, set up by rc.1 or rc.2, now gets DL-054's warning to move it.
- If Cursor or OpenCode change which files they read, the harness table (DL-041) changes with them.
- Amends DL-045 (the placement rule and its Pi and OpenCode claim) and DL-054 (the Cursor and OpenCode instruction lists).
