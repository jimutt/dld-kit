## Context

DL-045 places a new rule block in AGENTS.md if it exists, else in CLAUDE.md if it exists, else in a new AGENTS.md. The middle step exists because creating AGENTS.md next to CLAUDE.md makes Pi and OpenCode stop reading CLAUDE.md.

The 0.x upgrade check for DL-057 showed where this goes wrong. Every 0.x project has a CLAUDE.md, because the old dld-init appended its DLD section to it, and usually no AGENTS.md. `dld update --agent claude,codex` therefore puts the block into CLAUDE.md, which Codex does not read, and then warns that Codex cannot see it (DL-054). Cursor has the same problem. The README currently works around it by telling Codex and Cursor users to run `touch AGENTS.md` first. The same happens on `init` or `install-rule` in any project that has a CLAUDE.md and no AGENTS.md.

## Decision

- **Placement of a new block.** When no AGENTS.md or CLAUDE.md holds a block yet:
  - AGENTS.md, if it exists.
  - Else CLAUDE.md, if it exists and every harness the block is being installed for reads CLAUDE.md when there is no AGENTS.md (OpenCode and Pi).
  - Else a new AGENTS.md. This covers a CLAUDE.md-only project when the block is for Codex or Cursor, for example.
- **Claude Code** is unaffected. With the block in a new AGENTS.md beside an existing CLAUDE.md, Claude Code gets `.claude/rules/dld-workflow.md`, as DL-055 already plans, so each harness loads the rule once.
- **A warning for Pi and OpenCode.** When dld-kit creates AGENTS.md next to an existing CLAUDE.md and OpenCode or Pi is among the harnesses being installed, it warns that those harnesses now read AGENTS.md instead of CLAUDE.md. Anything they need from CLAUDE.md must move into AGENTS.md.
- **Existing blocks** are still refreshed where they are (DL-045). A block already in CLAUDE.md keeps its DL-054 warning for harnesses that cannot see it.
- **Docs.**
  - The README drops the `touch AGENTS.md` step from "Upgrading from 0.x".
  - Its Agents section describes the new placement.
- **Tests.**
  - Unit tests cover the placement for Codex, Cursor, OpenCode and Pi alone and combined, in projects with CLAUDE.md, AGENTS.md, both or neither, including the Pi/OpenCode warning.
  - The 0.x upgrade CLI test runs `update --agent claude,codex` without creating AGENTS.md first, and expects the block in AGENTS.md and only the old-section warning.

## Rationale

- A block in a file one of its target harnesses never reads is a broken install. The warning only reports it after the fact.
- The CLAUDE.md fallback stays for the case it was made for: projects that use only Pi or OpenCode and keep their instructions in CLAUDE.md.
- The 0.x upgrade is the most common path into 1.0 for existing users, and nearly all of them have a CLAUDE.md.

## Consequences

- Installing for Codex or Cursor in a CLAUDE.md-only project now creates AGENTS.md.
- A project that also uses Pi or OpenCode without naming them gets no warning, and those harnesses switch to reading AGENTS.md.
- Amends DL-045 (the placement rule).
