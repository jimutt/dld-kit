## Context

Each collaborator's skills bundle their own CLI, so a team runs several versions at once. A CLI that predates a format change does not fail: a 1.0 CLI in a project with timestamp IDs (DL-092) warns about the unknown `id_format` key (DL-079), rewrites `INDEX.md` without the timestamp records and skips their annotations. Nothing in the config can say "this project needs at least version X".

## Decision

- `dld.config.yaml` gains an optional `min_dld_version`, a version of the form `<major>.<minor>.<patch>` with no prefix or suffix. Any other value makes the config invalid.
- When the running CLI's version is lower, loading the project fails before the rest of the config is validated and before anything else is read or written, exit 1: `this project needs dld <min> or newer; this is dld <version>. Update dld-kit (npx dld-kit@latest update, or your plugin manager) and try again.`
- Versions compare by major, minor, then patch as numbers. A pre-release of the CLI (`1.2.0-rc.1`) counts as its base version (`1.2.0`). A CLI whose own version cannot be read counts as too old.
- The check is in the one function every project command loads the project through. It does not run in the commands that install or update dld-kit (`init`, `update`, `install-rule`, `create-config`), in `resolve-base`, in `--version` and `--help`, or in `session-context`, which only prints the rule and must not fail a session start.
- Without the key nothing changes.

## Rationale

- Stopping with an instruction is better than quietly producing a wrong index or audit. The cost of the check is one comparison.
- The update and install commands must keep working, or the message could not be acted on. An old CLI's own `update` would install its own old skills, so the message names `npx dld-kit@latest update`. The session hook stays silent: the first project command the agent runs gives the message.
- A plain three-part version keeps the comparison trivial and dependency-free. Nobody needs to require a pre-release.

## Consequences

- The guard starts with the release that adds it. A 1.0 CLI only warns about the unknown key, so the first switch to timestamp IDs still relies on the release notes telling everyone to upgrade.
- Later format changes can raise `min_dld_version` and be safe from every CLI at or after this release.
- DL-079 is unaffected: unknown keys stay warnings. This key is known and its check is an error only when the version is too low.
