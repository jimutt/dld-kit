## Context

Without arguments, `/dld-implement` implements every decision with `status: proposed` in the repository. On a team that includes other people's merged plans, which DL-066 deliberately treats as drafts until they are implemented. A user who meant "implement what I just planned" can end up with an agent rewriting code for someone else's feature.

## Decision

- Without arguments, `/dld-implement` collects the `proposed` records and splits them into two groups:
  - those added on this branch, meaning their file does not exist at the merge-base with the base branch (DL-071), committed or not;
  - all others.
- It asks with `AskUserQuestion` which to implement. This branch's records are offered as the default. The others are listed separately and are never selected by default.
- If no proposed records were added on this branch, it shows the others and asks. It never starts implementing without the user confirming the list.
- IDs and `tag:` arguments behave as now.

## Rationale

- "What I just planned" is almost always the records the current branch added. A confirmation step costs one answer and prevents the costly mistake.

## Consequences

- Implementing everything in one go now takes one more confirmation.
