## Context

DL-004 keeps bats as the behavioural oracle: a script is removed only when its bats tests pass against the CLI, and PRACTICES.md forbids weakening a bats test to make a port pass. The bats files call scripts as `bash "$SKILLS_DIR/<skill>/scripts/<name>.sh"`. A mechanism is needed to point those same tests at `dld` without editing each test.

## Decision

- With `DLD_BATS_TARGET=cli`, the bats test helper points `SKILLS_DIR` at a shim tree instead of `skills/`.
  - For each ported script, the shim tree holds a one-line script that runs `node dist/dld.mjs <command> "$@"`.
  - Unported scripts pass through to the real script.
  - The shim tree is generated from a list of ported commands. It is not hand-maintained.
- Without the variable, bats runs against the scripts as today.
- `npm run test:bats:cli` builds the bundle and runs bats in CLI mode. CI runs both modes.
- `test_common.bats` sources shell functions rather than running a script, so it stays bash-only. Its coverage moves to core unit tests.
- This slice ports `next-id` as the first command to prove the mechanism end to end.

## Rationale

- Swapping `SKILLS_DIR` keeps every bats file unchanged, so the oracle cannot be weakened by the port.
- A generated shim list gives a single, visible record of what has been ported.
- `next-id` exercises config loading, path resolution and the records directory, so it validates the whole skeleton.

## Consequences

- CI runs bats twice until the port completes.
- A script is deleted only after its tests pass in CLI mode, the skills call `dld` (workstream 7), and it is removed from the shim list.
