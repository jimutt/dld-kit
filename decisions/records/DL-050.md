## Context

Beyond Claude Code (DL-048), several harnesses can install skills from a repository or npm package (September 2026):

- **Codex.**
  - It reads a marketplace from `.agents/plugins/marketplace.json`, falling back to `.claude-plugin/marketplace.json`.
  - Its plugin manifest is an Agent Plugins `plugin.json` at the plugin root; `.codex-plugin/plugin.json` is the legacy location.
  - Skills come from the plugin's `skills/`. Codex tells the model each SKILL.md's path.
- **Copilot CLI.**
  - It looks for a marketplace in `marketplace.json`, `.plugin/`, `.github/plugin/` and, last, `.claude-plugin/marketplace.json`.
  - For a plugin manifest it checks an Agent Plugins root `plugin.json` first.
  - `${CLAUDE_PLUGIN_ROOT}` is an alias there, but `${CLAUDE_SKILL_DIR}` is not documented.
- **Pi.** `pi install npm:<package>` (or `git:`) installs a package whose `package.json` declares `"pi": { "skills": [...] }`. The keyword `pi-package` lists it in Pi's gallery. The `dld-kit` npm package already ships the portable `skills/`, including dld-common (DL-042).
- **Cursor** installs plugins only from its reviewed marketplace or from team marketplaces, not from a repository URL.
- **Antigravity** installs plugins only from a local path.

Without their own manifests, Codex and Copilot CLI fall back to `.claude-plugin/marketplace.json` and install the Claude Code variant. That variant relies on DL-046's sentence to resolve `${CLAUDE_SKILL_DIR}`, which works but is not exact.

## Decision

- **A root `plugin.json`** following the Agent Plugins schema: `$schema`, name `dld`, version, description, author, homepage, repository, license, keywords. It lists no components, so the conventional root `skills/`, the portable variant, is the plugin's skill set.
- **Two marketplaces** name that plugin, each declaring marketplace `dld-kit` with plugin `dld` whose source is the repository root (`./`):
  - `.agents/plugins/marketplace.json`, for Codex
  - `.github/plugin/marketplace.json`, for Copilot CLI
- **Generation.** `scripts/generate.ts` writes all three files from `package.json` fields, and `npm run check:generated` verifies them (DL-052).
- **No hooks in these plugins.**
  - Codex requires users to trust plugin hooks by hand.
  - The rule reaches both harnesses through the dld-init skill's `install-rule` (the AGENTS.md block, DL-045).
- **Pi.** `package.json` gains `"pi": { "skills": ["./skills"] }` and the keyword `pi-package`, so `pi install npm:dld-kit` (or `-l` for a project) installs the portable skills.
- **Not shipped in 1.0: Cursor and Antigravity manifests.** Their users install with `dld init` or `npx skills`.

## Rationale

- One Agent Plugins manifest over the committed portable `skills/` reaches both harnesses and adds no generated skill copy.
- Giving Codex and Copilot CLI their own marketplace files keeps them from installing the Claude Code variant.
- The Pi entry costs two lines, because the npm package already carries the skills.
- Manifests for Cursor and Antigravity would have no install path from this repository today.

## Consequences

- Codex and Copilot CLI copy the whole repository into their plugin caches, because the plugin root is the repository root.
- A Cursor manifest can follow if dld-kit is submitted to Cursor's marketplace.
