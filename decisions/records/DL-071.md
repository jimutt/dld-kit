## Context

`resolve-base` returns the upstream when it tracks a differently named branch, and otherwise the hard-coded `origin/main` (DL-027). `check-decision-edits` and `restore-decision-prose` fall back to a local `main` (DL-066). In a repository whose default branch is `master`, `develop` or `trunk`, `check-decision-edits` fails with "base ref 'origin/main' not found" while `resolve-base` still prints `origin/main` and exits 0. The skills treat the failure as "tell the user and continue", so prose protection is silently off in those repositories, and reindex compares against a branch that does not exist.

## Decision

- `dld.config.yaml` gets an optional key `base_branch`, a branch name such as `main` or `develop`.
- The base ref is resolved in this order, the first that applies winning:
  1. `--base`, where a command takes it.
  2. `base_branch`: `origin/<base_branch>` if that ref exists, else the local `<base_branch>`.
  3. The upstream, when it tracks a branch with a different name than the current one (DL-027's rule).
  4. The remote's default branch, from `git symbolic-ref refs/remotes/origin/HEAD`.
  5. `origin/main`, then the local `main` (DL-066's fallback).
- `resolve-base` prints the ref it picked only if it resolves to a commit. Otherwise it fails with exit 1, naming the refs it tried and suggesting `base_branch` or `git remote set-head origin --auto`.
- Every command that picks a base itself uses this one resolution: `resolve-base`, and `list-taken-ids`, `find-collisions`, `plan-renames`, `rename-decision`, `check-decision-edits` and `restore-decision-prose` without `--base`. `commit-reindex` and `find-stale-mentions` still require `--base`, which the reindex skill passes from `resolve-base`; leaving it out is now a usage error (exit 2).
- `base_branch` is a plain branch name: one that starts with `-` or `origin/`, contains whitespace or `..`, or starts or ends with `/` is a config error.
- The configuration spec documents `base_branch`, and the skills that report "base branch not found" point at it.

## Rationale

- Most repositories that do not use `main` have `origin/HEAD` set by `git clone`, so they work without configuration. The key covers the rest, such as a release branch that is not the remote default.
- A base that silently does not exist turns off the checks the user relies on. Failing names the problem and the fix.

## Consequences

- A repository with no remote, no `main` and no `base_branch` now gets an error from `resolve-base` where it used to get `origin/main`. Skills already handle a missing base by telling the user.
