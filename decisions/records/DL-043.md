## Context

`dld update` (DL-040) rewrites skills that already exist in a project. Those may be from an older or newer dld-kit, hand-copied before 1.0 (with `scripts/*.sh` and no version stamp), or edited locally. The generator's `writeOutput` already owns every `dld-*` directory in an output and deletes files it did not generate, but leaves emptied directories behind (DL-033). Projects set up by the old dld-init skill also carry a hand-written DLD block in CLAUDE.md.

## Decision

- In each skills directory, dld-kit owns the `dld-*` directories (as DL-033). `init` and `update` make them hold exactly the generated output: changed files are overwritten, missing files written, and other files removed. Local edits are overwritten, as the generated-file notice says (DL-044).
- Directories left empty by pruning are removed, bottom-up, up to but not including the skills directory. This applies to `npm run generate` too. `Context.fs` gains an operation that removes an empty directory and fails on a non-empty one.
- Before writing, `update` reads `metadata.dld-kit-version` from each installed `dld-*` SKILL.md and the stamp of each installed rule channel (DL-045). If any is newer than the running CLI (compared as semver), it refuses, naming the file and both versions; `--force` overrides.
- Missing or unparsable stamps (pre-1.0 copies, hand edits) count as older and are replaced. This is the migration path for copy and Tessl users: their `dld-*` directories are rewritten and the old `scripts/*.sh` are removed.
- If CLAUDE.md contains a `## DLD (Decision-Linked Development)` heading outside dld-kit's markers (the old dld-init block), `init` and `update` print a warning that the rule is now installed separately and the block can be removed. They never edit it.
- Writes are atomic (DL-015). Skills outside the `dld-*` directories are never read, changed or removed.

## Rationale

- Treating the `dld-*` directories as fully generated keeps updates simple and predictable. Merging local edits would need the old templates, and the notice already says not to edit.
- The downgrade guard stops an old global `dld` from silently replacing skills a teammate installed with a newer version.
- Removing empty directories keeps a removed skill from leaving a directory that some harnesses list as a broken skill.
- The old CLAUDE.md block may have been edited by the user and has no markers, so rewriting it could destroy their text; a warning is enough.

## Consequences

- Amends DL-033: emptied directories are now removed.
- The generator's output and pruning code is shared by `npm run generate`, `init` and `update`.
