## Context

The TypeScript code will be written largely by agents across many stacked branches. Without an enforced style, diffs fill with formatting noise and small inconsistencies accumulate. `tsc` strict mode catches type errors but not style or common lint issues.

## Decision

Use Biome as the single linter and formatter, configured in one `biome.json` at the repo root. `biome check` runs in CI and fails the build on errors; `biome check --write` is the local fix command. Use Biome's recommended rules as the starting point and deviate only with a comment explaining why.

Configuration lives in `biome.jsonc` (JSONC so it can carry comments) and is scoped to `src/`, `tests/cli/`, `scripts/` and root JSON files; the bash skills and docs are out of scope.

## Rationale

- One fast tool and one config file instead of ESLint + Prettier plus plugins.
- Deterministic formatting removes formatting from review and from agent diffs.
- Recommended rules give reasonable coverage without a rule-tuning project.

## Consequences

- Adds one development dependency.
- Some ESLint-ecosystem rules have no Biome equivalent; accepted, since strict TypeScript covers most of what matters here.
