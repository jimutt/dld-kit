## Context

`/dld-snapshot` writes two built-in documents: `SNAPSHOT.md`, a per-decision listing of every active decision (its Decision section, a condensed rationale and its code references), and `OVERVIEW.md`, a narrative synthesis with diagrams. `SNAPSHOT.md` was meant to read as the project's specification. In practice it is a shortened copy of the records:

- It does not apply amendments. In gillerkvitter, 69 of its 199 sections carry an "Amended by: DL-NNN" line over the original wording, so a reader still has to look up the amendment to know the current rule.
- It is large. gillerkvitter's is about 46k tokens for 209 records, four times its `OVERVIEW.md`, and it grows with the log.
- Nothing in DLD reads it. The skills read the records and `INDEX.md`; `OVERVIEW.md` already cites 208 of gillerkvitter's 212 decision IDs.

Three of the six projects that use DLD never generated one.

A test on gillerkvitter, with its snapshot regenerated the same day, had two agents answer the same 20 questions in the repository, one with `SNAPSHOT.md` and one without. The questions covered decision details, constraints, the current rule after amendments and supersessions, and cross-cutting flows, and were written from the records. A blind grader scored them 40 and 39 of 40, the one point on a borderline detail. The agent that had `SNAPSHOT.md` read its first 30 lines to check it was current and nothing more; both worked from `INDEX.md`, the records and the code, and the one with the file read `OVERVIEW.md` in full.

`snapshot_artifacts` already lets a project define further documents with its own prompt, which is where a fuller specification belongs: one that merges amendments needs a prompt of its own.

## Decision

- `OVERVIEW.md` is the only built-in snapshot document. `/dld-snapshot` no longer writes `SNAPSHOT.md`, and it keeps generating the custom artifacts in `snapshot_artifacts`.
- `SNAPSHOT.md` is no longer a reserved name: a `snapshot_artifacts` entry may use it. `OVERVIEW.md` and `INDEX.md` stay reserved.
- When `decisions/SNAPSHOT.md` exists and no `snapshot_artifacts` entry is titled `SNAPSHOT.md` (compared without regard to case), `/dld-snapshot` says the file is no longer generated and asks with `AskUserQuestion` whether to delete it. If the user keeps it, it is left untouched, and the question comes back on the next run. A file that a custom artifact defines is generated like any other artifact and never offered for deletion.
- `detect-snapshot-changes` reports `mode: full` when `OVERVIEW.md` is missing; a missing `SNAPSHOT.md` no longer matters. `update-snapshot-state` records `OVERVIEW.md` and the custom artifacts named on its command line.
- The always-on rule, the skill descriptions, the README and the docs stop mentioning `SNAPSHOT.md` as a built-in document. The configuration docs keep the onboarding guide as the example custom artifact, and add no template that rebuilds the old snapshot.
- dld-kit's own `decisions/SNAPSHOT.md` is deleted.

## Rationale

- A document that agents skip and that repeats the records in shortened form costs a model run and review time on every snapshot without giving readers anything `OVERVIEW.md`, `INDEX.md` and the records do not.
- Teams that want a detailed specification need a prompt written for it, and `snapshot_artifacts` already provides that. Not shipping a template for the old format keeps the documentation from steering users back to it.
- Asking before deleting, and never for a file the user defined as an artifact, keeps an upgrade from removing something the user chose to keep.

## Consequences

- Amends DL-025: `detect-snapshot-changes` and `update-snapshot-state` no longer use `SNAPSHOT.md`.
- Amends DL-070: proposed decisions are no longer listed in a `SNAPSHOT.md`; `OVERVIEW.md` keeps its Planned Direction section and custom artifacts still receive proposed records.
- Projects that upgrade keep an unmaintained `SNAPSHOT.md` until they answer the question, or define it as a custom artifact.
- `/dld-snapshot` runs faster and costs less, since it writes one built-in document instead of two.
- The skill keeps its name: it still takes a snapshot of the log, now as `OVERVIEW.md` and the custom artifacts.
