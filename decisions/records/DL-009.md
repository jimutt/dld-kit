## Context

`common.sh` reads `dld.config.yaml` with `grep | sed`, which handles flat `key: value` lines and a `namespaces` list. The documented schema (docs/framework/project-configuration.md) also includes `implement_review` and `snapshot_artifacts`: a list of maps whose `prompt` values use folded `>` block scalars, which the bash approach cannot parse. The CLI must bundle into a single zero-dependency file (DL-003).

## Decision

- Parse the file with the `yaml` npm package. It is a devDependency, bundled into `dist/dld.mjs` by esbuild, so the published package keeps no runtime dependencies.
- Validate the parsed value into a typed `Config` object, without type assertions (PRACTICES.md):
  - `decisions_dir` (string, required)
  - `mode`: `flat` or `namespaced` (required)
  - `namespaces` (string list, required non-empty when `mode` is `namespaced`)
  - `annotation_prefix` (string, default `@decision`)
  - `implement_review` (boolean, default `true`)
  - `snapshot_artifacts` (list of `{title, prompt}`, default empty)
- Unknown keys are ignored.
- A missing config file fails with the same message the scripts print: `dld.config.yaml not found. Run /dld-init first.`
- Any other invalid value fails with a message naming the key and the expected shape.
- Core exposes the derived paths: decisions directory, records directory, and per-namespace records directories.

## Rationale

- A real parser handles quoting, comments and block scalars the way users expect. A hand-written subset parser would be ours to maintain and a source of edge-case bugs.
- The cost is bundle size (the unminified bundle grows to about 270 KB), which does not matter for a file shipped inside skills.
- Validating up front turns a malformed config into one clear error instead of a confusing failure deep in a command.

## Consequences

- `yaml` resolves to its CommonJS build under Node, which calls `require()` for Node built-ins. The esbuild banner defines `require` via `createRequire` so the ESM bundle can load it.

- The CLI is stricter than bash. An invalid `mode` is now an error where the scripts silently carried on. That is intended.
- Adding a config key means updating the validator and the configuration doc together.
