## Context

Skills installed through `npx skills` or a plugin marketplace arrive without an npm install, so they cannot assume a `dld` on `PATH` (docs/plan/v1.md, "How skills reach the TypeScript code"). The build already produces `dist/dld.mjs`, a single zero-dependency ESM file of about 330 KB that runs on Node 20+. The generator (DL-031 to DL-033) produces the committed skill outputs, but today it only copies files from `templates/`.

A survey of comparable frameworks (September 2026) found two camps: skills that ship their helper code and call it by a path relative to the skill (Anthropic's skills, obra/superpowers, BMAD's skill scripts, and the Agent Skills specification itself), and tools that require a globally installed CLI and then need version-skew detection and an update command (OpenSpec, agent-browser). No surveyed project uses a PATH-first wrapper with a bundled fallback, which the plan had proposed.

## Decision

- The skills ship the bundled CLI and always use it. There is no PATH lookup and no `npx`. A globally installed `dld` (npm) remains the entry point for people, CI and `dld init`/`dld update`, never something the skills depend on.
- There is one copy per output, in the internal `dld-common` skill: `dld-common/scripts/dld.mjs`. The generator adds it to every adapter's output from `dist/dld.mjs`.
- `npm run generate` and `npm run check:generated` build `dist/dld.mjs` first, so the committed copies always match the source. The drift check therefore also catches a `src/` change whose skills were not regenerated. The esbuild build is deterministic for pinned inputs; if it ever is not, the check fails loudly rather than drifting.
- Skills that run the CLI declare `compatibility: Requires Node.js 20+ and git.` (with the `gh` note kept for dld-reindex).

## Rationale

- Calling the copy that ships with the skill means the CLI always matches the skill text: no version skew, no global install, and no network at call time. It is also the pattern the Agent Skills specification describes.
- One shared copy keeps each output to about 330 KB of generated JavaScript, instead of one copy per skill (about 3.6 MB per output, and about 7 MB changed in git for every CLI change).
- Building before generating makes a stale bundle impossible to commit unnoticed.

## Consequences

- A skill installed without `dld-common` cannot run; DL-036 makes each skill detect that and tell the user how to install it.
- Every change under `src/` changes two committed copies of `dld.mjs` (in `skills/` and `.claude/skills/`).
- The plan's "PATH-first with bundled fallback" is replaced by this decision.
