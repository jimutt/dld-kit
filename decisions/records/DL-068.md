## Context

DL-066 and DL-067 define when a record's prose is protected and how strictly. Agents only follow that if they meet it at the right moments: before editing a record, and before they consider their work finished.

## Decision

- The always-on rule gets one line: records not yet on the base branch are drafts and can be edited, frontmatter can always be updated, and the prose of records on the base branch follows the project's `decision_edits` setting (default: never edit; amend or supersede instead).
- `dld-adjust` decides whether to ask using `check-decision-edits <ID>` (draft or integrated) and `decision_edits`, replacing its "pushed to any remote branch" test. Deprecated and superseded drafts are edited like any other draft.
- `dld-implement`, `dld-adjust`, `dld-decide`, `dld-plan` and `dld-audit-auto` run `check-decision-edits` as a last step. When it lists records, the agent acts on `decision_edits`: under `block` it restores the body with `dld restore-decision-prose <DL-NNN>...` and records an amendment instead if the change is still needed; under `ask` it asks; under `allow` it lists the edits in its report. `dld-audit-auto` always restores.
- The README, the record-format spec, the configuration spec, the concept docs and the FAQ say "immutable once integrated" instead of "immutable once accepted", and document `decision_edits`.
- New internal command `dld restore-decision-prose [--base <ref>] <DL-NNN>...`: puts back the body of each integrated record as it is at the merge-base, keeping the current frontmatter, and restores a deleted record whole. It refuses drafts before writing anything. Restoring by hand from `git show` is easy to get wrong when the frontmatter also changed.
- `dld-implement` no longer calls an `accepted` record immutable while it is still a draft.

## Rationale

- The rule line reaches ordinary sessions, where the unwanted edits happened. The skill steps catch edits at the moment work is called done.
- One command gives every skill the same answer, instead of each skill testing git its own way.

## Consequences

- Sessions that edit records without running a skill rely on the rule line alone. A Claude Code Stop hook or a CI check could add a hard stop later.
