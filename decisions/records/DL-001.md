## Context

1.0 replaces the bash helper scripts with a TypeScript CLI and library (docs/plan/v1.md). The shipped code needs one supported runtime. Every harness DLD targets already assumes a JavaScript runtime, and the development loop benefits from Bun's fast test runner and TypeScript support. But Bun is not what users have installed by default, and a CLI that silently depends on Bun behaviour breaks for Node users.

## Decision

Node.js 20 or newer is the only supported runtime for everything shipped. Compile to ESM targeting the language level Node 20 supports (ES2023).

Bun is used for development only: running tests and local scripts. Code under `src/` must not use Bun-specific APIs (`Bun.*`, `bun:*` imports) — only Node built-ins (`node:fs`, `node:path`, `node:child_process`, …) and standard JavaScript. The built CLI is always exercised under `node` in CI, so a Bun-only behaviour cannot reach users unnoticed.

## Rationale

- Node is the most widely installed JS runtime and the one package managers, Homebrew and harnesses assume. Node 20 is the oldest line still broadly deployed; OpenSpec and BMAD set the same floor.
- Bun runs TypeScript directly and its test runner is fast, which keeps the development loop short, especially for agent-driven work.
- Restricting `src/` to Node APIs keeps the two roles separate: Bun can be swapped for another dev tool without touching shipped code.

## Consequences

- Users need Node 20+; bash and jq are no longer required once the port completes.
- Contributors need both Node and Bun installed.
- Newer Node APIs (e.g. those only in Node 22+) are off-limits unless feature-detected.
