## Context

DL-001 makes Node.js 20 or newer the runtime, and DL-005 runs the CLI integration tests on Node 20 and 22. Node 20 reached end-of-life on 30 April 2026, so 1.0.0 would promise support for a runtime that no longer gets security fixes. Raising the floor after 1.0.0 would count as a breaking change, and the next line, Node 22, reaches end-of-life in April 2027.

## Decision

- Node.js 22 or newer is the supported runtime for everything shipped. `package.json` declares `"engines": { "node": ">=22" }`, esbuild targets `node22`, and `@types/node` is pinned to the 22.x line, so APIs newer than the floor fail to typecheck. The compiled language level stays ES2023.
- The CLI integration tests run on Node 22 and 24. The other CI jobs run on 22.
- **Support policy:** dld-kit supports the Node.js release lines that are in active or maintenance LTS. When a line reaches end-of-life, a minor release may raise the floor past it; the changeset says so. Raising the floor while a line is still maintained needs a major version.
- The skills' compatibility lines, the setup text the adapters render, the README, the install guide, the contributing guide and the practices say Node.js 22+.
- Bun stays a development tool only, as DL-001 says.

## Rationale

- Promising an end-of-life runtime in 1.0.0 would either keep dld-kit on old APIs and CI images or force a 2.0.0 for no user-visible reason.
- Tying support to Node's own LTS schedule tells users when a version will be dropped, and keeps routine floor raises out of the major-version track.

## Consequences

- Amends DL-001 (the runtime floor and the `@types/node` pin) and DL-005 (the Node versions CI tests).
- Users still on Node 20 must upgrade Node to use 1.0.0.
- Node 22's end-of-life in April 2027 can be handled in a 1.x minor release.
