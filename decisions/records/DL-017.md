## Context

DL-011 requires `-h`/`--help` on every command. The skeleton detects them by scanning the raw arguments before parsing. `create-decision` is the first command with options that take values (`--title`, `--tags`, ...). With raw scanning, a value that happens to be `-h` or `--help`, such as `--title --help`, would print help instead of being parsed as the value.

## Decision

- `parseCommandArgs` adds a `help` boolean option (`-h`, `--help`) to every command's options and parses once.
- If `help` is set, it throws a signal that the dispatcher turns into the command's usage on stdout with exit 0. Commands never see the flag.
- `--help` given as the value of an option (`--title=--help`) is a value, not a request for help.
- The raw-argument scan in the dispatcher is removed.

## Rationale

- Only the parser knows which tokens are option values, so help detection belongs there.
- Adding the option centrally keeps every command consistent without each one declaring it.

## Consequences

- A command that fails to call `parseCommandArgs` would not get `--help`. Every command parses its arguments, and a CLI test checks `--help` for every registered command.
