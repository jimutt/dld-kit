## Context

The dld-init skill is how skill-channel users (`npx skills`, plugin marketplaces) set up a project. It runs the setup commands and then appends a hand-copied rule block to CLAUDE.md, a copy that has already drifted from `templates/rules/dld-workflow.md`. This repository has the same hand-written block in its own CLAUDE.md.

## Decision

- **dld-init skill.**
  - The skill keeps its interactive steps: flat or namespaced, the namespaces, and the optional PRACTICES.md.
  - The hand-written CLAUDE.md step is replaced by `{{dld}} install-rule --agent <harness>` (DL-045). The agent names the harness it is running in, and asks the user when unsure or when the team uses several.
  - The skill no longer contains the rule text.
  - Its prerequisites and next steps mention `npx dld-kit init` as the npm route, which also installs the skills.
- **This repository.**
  - `npm run generate` also writes `.claude/rules/dld-workflow.md` from the template, using the same renderer as `dld install-rule`, and `npm run check:generated` covers it.
  - The DLD section of CLAUDE.md is removed. CLAUDE.md keeps the note that `decisions/` is dld-kit's own log.

## Rationale

- One source for the rule text, rendered by one piece of code, ends the drift between the skill's copy, CLAUDE.md and the template.
- The agent knows which harness it runs in; the CLI cannot tell from inside a skill.
- Dogfooding the owned rule file exercises the Claude Code channel on every session in this repository.

## Consequences

- Rule changes reach this repository through `npm run generate`, and user projects through `dld update` or `dld install-rule`.
