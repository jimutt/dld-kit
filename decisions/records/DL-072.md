## Context

DL-043 has `dld update` own every `dld-*` directory in a skills layout: it overwrites them and prunes any that the current version does not generate. A user's own skill named `dld-custom` is therefore deleted, and the report says only "1 removed". DL-055 has dld-kit own `.claude/CLAUDE.md` while it carries dld-kit's stamp, and rewrites it on every update. Claude Code users commonly keep their own project instructions in that file, and an appended line was silently lost when the review tested it.

## Decision

- **Pruning.** `update` removes a `dld-*` directory that the current version does not generate only when it is dld-kit's:
  - its SKILL.md carries a `metadata.dld-kit-version` stamp, or
  - its name is one of the skills dld-kit has shipped, in any version (the 0.x names included), kept as a list in the generator.
  Any other `dld-*` directory is left in place, with a warning naming it.
- **Reporting.** `init` and `update` name every directory and file they remove, not only a count.
- **`.claude/CLAUDE.md`.** dld-kit rewrites the file only when its content, apart from the version in the notice, is exactly what some dld-kit version generated: the notice and the `@../AGENTS.md` import. If the user added anything, the file is left unchanged, with a warning that it holds user content and that dld-kit no longer maintains it. If the import line is missing, the warning says to add it back. The DL-045 once-per-harness checks treat the file as user-owned from then on.
- Unit tests cover a user `dld-*` skill next to dld-kit's, a 0.x unstamped copy, and an edited `.claude/CLAUDE.md`.

## Rationale

- Deleting files the user wrote is the one thing an update must never do. The stamp and the list of shipped names identify everything dld-kit has ever installed, so the 0.x migration still works.
- Leaving an edited `.claude/CLAUDE.md` alone costs at most a warning, where overwriting it loses the user's instructions.

## Consequences

- A stale skill dld-kit renamed but forgot to add to the list of shipped names would be left behind with a warning, instead of deleted. The list is checked against the templates in tests.
