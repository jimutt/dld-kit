## Context

`regenerate-index`, `update-status` and `create-decision` are the first ported commands that read or write decision records. The scripts extract fields with `grep | sed`, replace the `status:` line in place, and write new records with `echo`. The bats tests check that `update-status` changes only the status line and preserves other fields and the body. Users edit these files by hand, so they contain whatever formatting the user chose.

## Decision

- **Reading.** Core splits a record into frontmatter and body at the first two lines that are exactly `---`. It parses the frontmatter with the `yaml` package (DL-009) and validates it into a typed `DecisionRecord`: `id`, `title` and `status` required; `timestamp`, `supersedes`, `amends`, `namespace`, `tags` and `references` optional with empty defaults. A record that cannot be parsed or validated fails with an error naming the file.
- **Editing metadata.** Changes to existing records are line-level edits inside the frontmatter block. For example, `update-status` replaces the single `status:` line. Every other byte of the file, including the body and the user's formatting and comments, is left unchanged. Core never re-serialises a whole frontmatter block.
- **Creating.** New records are rendered from a fixed template with the same line order and layout as `create-decision.sh`. A title is written double-quoted, with `\` and `"` escaped.
- Status values are the ones the scripts accept: `proposed`, `accepted`, `deprecated`, `superseded`.
- `create-decision` accepts only IDs of the form `DL-<digits>`, and a namespace that is a single directory name (not empty, `.`, `..`, or containing a separator). The script accepted anything, so an ID or namespace could point outside the records directory.
- `update-status` fails if the frontmatter has no `status:` line. The script reported success without changing anything.

## Rationale

- A real parser reads quoting, lists and comments correctly, where `grep | sed` breaks on anything unusual.
- Re-serialising YAML would reformat users' hand-edited records and produce noisy diffs. Line-level edits keep diffs to the one line that changed, which is what the bats tests and the `/dld-*` skills rely on.
- A fixed template keeps new records identical to the ones the scripts produce.

## Consequences

- The intended differences from the scripts, all for malformed input, are the ID and namespace checks and the missing-status failure above, plus these two: a title containing `"` produced invalid YAML in `create-decision.sh` and is now escaped; a record with unparseable frontmatter now fails loudly instead of yielding a partial INDEX row.
- Metadata edits beyond `status` (e.g. `references`, used by reindex) will need their own line-level edit functions as they are ported.
