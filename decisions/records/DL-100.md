## Context

The skills, the always-on rule and the docs describe IDs as `DL-NNN` and tell agents to run `next-id` and increment. `/dld-init` creates the config through `create-config <mode> [namespaces]`. The README tells teams to run `/dld-reindex` when two branches pick the same ID. With `id_format` (DL-095) and `min_dld_version` (DL-098) a project can opt out of that problem, and the instructions have to hold for both forms.

## Decision

- **Init.** `/dld-init` asks which ID form the project uses, with sequential first as the default and a one-line trade-off for each: short, memorable IDs that can clash between branches, or long opaque IDs that do not.
  - `create-config` gains `--id-format <sequential|timestamp>`. Without it the config has no `id_format` key, as now.
  - With `timestamp` it also writes `min_dld_version` set to the first release that supports timestamp IDs.
- **Skills.**
  - `DL-NNN` stays the placeholder for "a decision ID". Each skill that creates, looks up or annotates decisions says once that an ID is either `DL-` plus a number or a timestamp ID, and that IDs are copied from command output, never retyped or made up.
  - `/dld-decide`, `/dld-plan` and `/dld-retrofit` take each ID from `next-id` and no longer tell the agent to increment.
  - `/dld-reindex` says that timestamp projects rarely need it, and that it still applies to branches opened before a switch.
  - `/dld-audit` and `/dld-audit-auto` describe near-misses and the canonical spelling for both forms (DL-094), report a local timestamp ID far ahead of the clock (DL-095), reserved file names (DL-099) and a `timestamp` config without `min_dld_version`. Audit-auto fixes a timestamp ID typo only when exactly one existing ID differs from it by one character.
  - `/dld-status` shows the configured ID form.
- **Rule.** The always-on rule keeps its `DL-XXX` placeholder and names both forms once.
- **Docs.** The record format spec and the configuration spec describe both forms, `id_format`, `min_dld_version`, the order across forms (DL-093) and the reserved file name. The README's team paragraph offers timestamp IDs as the way to avoid clashes and `/dld-reindex` as the repair for sequential ones. A new `docs/id-formats.md` covers choosing a form, switching an existing project and upgrading every collaborator first.
- dld-kit's own log stays sequential for now.

## Rationale

- Sequential stays the default until a major release, so init must present it first and make the other an explicit choice.
- Writing the version guard with the timestamp choice protects new projects without anyone having to know the key exists.
- Keeping one placeholder avoids rewriting about 120 lines of examples for no gain in clarity.
- Agents copying IDs matters more with opaque IDs: a retyped 13-character key is easy to get wrong, where `DL-047` was not.

## Consequences

- Every generated skill copy changes, so the release regenerates `skills/`, `.claude/skills/` and `claude-plugin/`.
- Existing projects are not asked anything. They switch by editing `dld.config.yaml` as `docs/id-formats.md` describes.
- Whether timestamp becomes the default for new projects is left for 2.0.
