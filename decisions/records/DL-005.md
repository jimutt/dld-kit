## Context

The current workflow runs only bats, on pull requests and pushes to `main`. 1.0 work lands on the `v1` integration branch through stacked PRs, and adds TypeScript, a build, and a published package.

## Decision

The GitHub Actions workflow runs on pull requests and on pushes to `main` and `v1`, with these steps:

- install dependencies from the lockfile (frozen)
- Biome check (lint and format)
- `tsc --noEmit`
- `bun test`
- build, then the CLI integration tests under `node` on a Node 20 and Node 22 matrix
- the bats suite (until retired)
- `npm pack --dry-run`, failing if the tarball contains files outside the `files` allowlist or is missing the built CLI

## Rationale

- Pushes to `v1` must be tested because stacked PRs merge into it before anything reaches `main`.
- Node 20 is the floor and Node 22 is the current LTS; testing both catches API and behaviour differences at the edges of the support range.
- A pack dry-run catches publishing mistakes before a release, when they are cheapest to fix.

## Consequences

- CI takes longer than the bats-only job; the matrix applies only to the Node integration step to keep it short.
- The Node matrix is revisited as Node versions reach end of life.
