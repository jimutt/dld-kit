## Context

`list-taken-ids.sh` adds the decision IDs in files touched by open pull requests to the IDs taken on the base branch, so a renamed decision does not land on an ID another open PR is about to claim. It shells out to `gh pr list --state open --base <base without origin/> --json files --limit 100 --jq '.[].files[].path'`, keeps paths under the records directory and extracts every `DL-<digits>` from them. The scan is skipped, with `[dld-reindex] open PRs not scanned: <reason>` on stderr and exit 0, when `gh` is not installed, `origin` is not a GitHub remote (`github.com[:/]`), or `gh auth status` fails. If `gh pr list` itself fails, the script discards the error and prints nothing, so the user believes open PRs were checked.

Core has no way to run a process other than git (DL-008).

## Decision

- `Context` gains `gh(args)`, shaped like `git(args)`: it runs `gh` in `cwd` and returns stdout. A non-zero exit throws a `DldError` subclass carrying gh's stderr. A missing `gh` binary throws a distinct error type, so core can tell "not installed" from "failed". The real implementation uses `execFileSync` with a timeout (60 seconds) and `GH_PROMPT_DISABLED=1`; a timeout is reported as a failure.
- The open-PR scan keeps the script's skip reasons, checks and notice text, in the same order. Whether gh is installed is checked with `gh --version`; the GitHub-remote check reads `git remote get-url origin`.
- PRs whose head branch is the current branch are not counted (`--json files,headRefName`). The script counted the branch's own open PR, so every record it added collided with itself.
- `gh pr list` is called without `--jq`; core parses the JSON itself and reads `files[].path` from each PR, tolerating PRs with no `files`. Paths are kept when they start with the records directory (root-relative, `/`-separated) followed by `/`, compared literally rather than as a regular expression.
- When `gh pr list` fails, times out or returns output that is not the expected JSON, the scan is skipped with the same notice and a reason naming the failure (e.g. `gh pr list failed: <first line of stderr>`). Base-branch IDs are still printed and the exit code stays 0.
- Core returns the skip reason; the CLI prints the notice (DL-007).
- Tests use a fake `gh` in the Context for every branch: not installed, not a GitHub remote, not authenticated, list failure, malformed JSON, and a successful scan.

## Rationale

- A narrow `gh` method mirrors `git` and keeps process execution out of core, as DL-008 intends for every external tool.
- Parsing JSON in TypeScript removes the dependency on gh's `--jq` support and makes the parsing testable.
- A silent failure of the PR scan is the one case where the user is misled about how safe the chosen IDs are; reporting it costs nothing.

## Consequences

- The open-PR scan is still best-effort and limited to 100 PRs and to `github.com` remotes, as before.
- `dld list-taken-ids` prints a notice in one case where the script printed none.
